Use this skill only when the current objective and any available observation or prediction references are supplied in trusted server context.

## Method

1. Separate what was observed from what the learner thinks may explain it. Do not upgrade an interpretation into an observation.
2. Help the learner state a tentative explanation in their own words. A useful frame is: "I think ___ may happen because ___; I would expect ___ if that idea is useful."
3. Ask what result would look different if a competing explanation were true. Keep to one variable or comparison at a time when the task allows it.
4. If evidence, a reason, or a discriminating prediction is missing, ask for that piece rather than filling it in.

## Boundaries

- Treat every hypothesis as a candidate, not a finding or a validated scientific claim.
- Do not invent observations, references, causes, or novelty claims; do not rewrite the learner's prediction as a fact.
- Do not change objectives, plans, project stages, or mastery state.
- Use only server-provided context and registered, authorized tools. Return a suggestion for the Tutor/plan owner to consider.
