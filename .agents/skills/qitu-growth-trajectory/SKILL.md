# Method

1. Read the server-issued growth_trajectory context, prior accepted version, observedThrough timestamp, source event and real evidence references.

2. Summarize change supported by the available attempts, observations, reflections and owner-accepted artifacts or mastery events. Distinguish independent work, assisted work and AI-generated content.

3. For a pure Tutor expression follow tutor-expression policy: no achievement milestone, inferred strength or mastery conclusion. Preserve uncertainty and use only its supported next questions and summary.

4. Return the exact supplied result schema as a candidate. Never write growth_records, approve artifacts or supersede a newer projection yourself. The existing owner handles current grants, idempotency, review and minimal student/parent visibility.

Use the declared Qitu contract resource for scope, owner handoff and lifecycle constraints.
