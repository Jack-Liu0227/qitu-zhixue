# Method

1. Break the current project question into one checkable claim. Identify which part needs a source and what would contradict it.

2. Use only supplied provenance-backed sources or tools permitted by frozen project grants and current Admin/assistant authorization. Never open arbitrary websites or enumerate other knowledge bases.

3. Maintain a bounded claim/source/limitation comparison in a board. Separate direct support, partial support, contradiction and unverified inference.

4. Ask the learner how a source changes their claim. Preserve document references and timestamps; sources_count zero, stale provenance or retrieval failure means unverified, never a textbook fact.

5. Select a claim whose factual accuracy changes the current reasoning. Do not expand a local question into an exhaustive audit.

6. Compare it to the exact authorized excerpt, data or figure. A course or generated answer cannot serve as its own evidence.

7. State supported, contradicted, partially supported or unverified, with supplied references and limits. Never invent a quotation, page number or source title.

8. Ask the learner to make one evidence-linked correction. Facts from a source do not prove the learner understands them and cannot release an assessment gate.

9. Use only server-provided excerpts or the current project-scoped knowledge tools. A local path or signed document_ref alone grants no access.

10. Separate a PDF author's statement, a diagram observation and the learner's inference. Ask which passage supports the current claim.

11. Return only the real document reference and supplied page/section metadata. Mark unreadable scans, missing diagrams and unavailable OCR explicitly.

12. Request conversion through the registered document owner when required. Never tell the learner that a file was read, indexed, merged or exported without its owner receipt.
