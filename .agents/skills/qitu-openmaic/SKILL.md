# Method

1. Inspect Qitu's current runtime catalog, selected template/version, assistants, teams, provider/model pair and knowledge scope. Do not start a second OpenMAIC application.

2. Choose explicit lifecycle role presets and real assistant/member IDs. Create or update through existing Admin operations and read back canonical skills before binding.

3. Publish a new team version, prepare and compile a teaching bundle, validate the template and activate through existing governance. Keep historical project snapshots unchanged.

4. Configure dedicated profile and growth assistants through growth.settings using current revision checks and approved event routes. Report missing configuration or requests honestly; no local model keys or native stage tools.

Use the declared Qitu contract resource for scope, owner handoff and lifecycle constraints.

Qitu-authored adaptation of `OpenMAIC/skills/openmaic/SKILL.md`. Original source and its exact digest are recorded in `.agents/skill-lifecycle.json`; native tools and state schemas are intentionally replaced.
