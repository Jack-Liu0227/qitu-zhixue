# P2：试点验证、观测与发布门槛（Planned）

## 目的

用一个固定项目验证教学价值、系统可靠性和权限安全，再决定是否扩展模板与 Agent 能力。

## 工作项

- 建立 4 周桌面互动机器人 fixture：模板、计划、知识目标、证据、rubric 和教师账号。
- 覆盖从意图确认到作品归档的端到端测试，以及 8 周计划的扩展测试。
- 记录关键指标：计划生成成功率、理论门禁通过率、实践完成率、证据补交次数、教师复核耗时、项目完成率和失败恢复率。
- 对 AI 评审与教师最终结论进行抽样一致性检查；保留来源证据和模型版本。
- 验证学生、教师、家长、管理员的最小可见范围和敏感访问审计。
- 为 demo、mock、真实 Team Runtime 结果设置清晰标识，禁止混淆。

## 发布门槛

- 一条真实端到端链路通过：计划、门禁、实践、作品版本、评审候选、教师确认、成长记录。
- 关键状态转换、幂等、权限和未成年人数据测试通过。
- 所有页面具备 loading、empty、error、offline、permission-denied 状态。
- `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm check:basepath` 的执行结果已记录；UNC 环境限制需如实记录。
- 试点复盘明确继续、调整或暂停每项迁移能力的决策。

## 依赖与交付物

- 依赖：至少完成 P0 闭环和一个 P1 模板。
- 交付物：fixture、E2E/集成测试、指标面板或导出、权限审计报告、试点复盘和下一阶段 Issue。
