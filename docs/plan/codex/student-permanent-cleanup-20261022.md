# 学生历史记录永久清理与导师恢复

2026-10-22。用户要求恢复测试账号的光学导师配置，恢复会话删除，支持永久删除项目和草稿，并显示对应封面。已部署到 `study-remote`，8 个服务已重启，本文记录实际验收范围。

## 原因与配置修复

两个光学项目的历史绑定指向没有发布运行时快照的团队，缺少完整教学合同。课程明确指定的开场助手未进入团队。四位光学导师同时绑定整套技能，内容合计 26671 字符，超过 24000 字符的运行时预算，导致团队发布失败。

通过 Admin owner API 补入课程明确指定的助手，按导师职责配置已发布的 canonical skills，发布不可变团队版本，按该课程已有的 `optics-16x60-v2` 排期生成、校验、启用教学合同，再逐项恢复这两个历史项目。没有更改课程版本或增加知识库授权。

历史项目还没有对应的学习计划。新增显式、幂等的 owner 恢复接口，复用 `LearningPlanService.attachConfirmedProjectPlan`，从项目冻结合同生成计划。只允许尚处于意图已确认阶段且缺少计划的项目创建计划；已有计划必须通过冻结内容一致性检查。恢复不创建正式项目、不补造掌握度、课时完成或作品批准事实。

真实浏览器检查发现，显式传入探索 ID 时仍会先读取“继续学习项目”，从而抢占模板探索上下文。入口现在优先读取并授权明确指定的探索，默认继续学习选择不参与该请求。4 项探索回归通过，覆盖已有继续学习项目及跨对象拒绝。

第一课的观察/意图目标不属于理论或实践测验目标。原先在正常对话前读取待答题时错误进入测验范围检查，导致流式回复提前失败。现在仅对当前课时的测验目标读取待答题，保留出题 owner 的严格校验。引导对话已通过真实冻结模型请求。

## 学生操作

- AI搭档会话历史右侧“删除”会永久清除会话和聊天内容。正式项目、作品和独立判分记录保留；探索草稿会一并删除。重新进入正式项目会创建新的空会话。
- 我的项目在每条记录下显示“永久删除”。正式项目同时清理计划、对话、作品、项目证据和关联学习记录；草稿按探索/计划各自 owner 清理。
- 支持选择本页多条记录后“永久删除所选”。执行前明确确认范围与不可恢复性，逐条核对回执；部分失败显示实际成功数量并停止后续操作。原“收纳”功能保留。
- 已有 18 个正式项目来自不同历史探索/种子数据，不能仅按标题去重。原有历史数据不自动批量删除，用户可按需清理。
- 封面优先读取 Admin 的模板版本、模板及平台素材配置；未配置的旧项目显示主题插图。封面只参与展示，不参与任何教学授权判断。

## 接口与约束

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/student-history/conversations` | 只读真实存在的本人会话，按最后对话时间排序，最多 100 条，不创建空会话 |
| `DELETE /api/v1/student-history/:kind/:id` | `project`、`exploration`、`plan` 或项目 `conversation`；要求学生身份、对象归属和幂等键 |
| `POST /api/v1/projects/:id/teaching-plan/recovery` | 恢复本人已冻结项目的缺失计划，要求幂等键，验证真实 owner 回读 |

删除在一个数据库事务内完成并写入最小审计。不存在或越权对象统一拒绝；已确认探索、已关联项目的计划不能通过草稿删除路径清理。运行中的团队或资料处理任务阻止删除。共享资料保留归属，不能误删其他项目、学生或 Admin 的资料。

团队删除依据实际运行租约检查任务和消息；排队中的任务可随本人会话/项目清理，邮箱待处理计数同步扣减，避免空队列仍显示待处理。

迁移 `0047_permanent_history_cleanup` 允许判分记录脱离被删除的会话，保留独立学习事实；项目增加技术性的会话代次。旧请求不能在删除后重用旧会话和回合 ID。实际清除对话内容、会话、相关候选和可识别的重放缓存，不设置 `deleted_at`。审计仅保留操作元数据。

技能预算校验前移到助手保存和运行时解析，超预算返回 `ASSISTANT_SKILL_BUDGET_EXCEEDED`，不再表现为发布团队时的通用 500 错误。
