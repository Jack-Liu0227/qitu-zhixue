## 学生应当经历的完整过程

1. AI 从当前冻结课时的学习目标和授权知识库解释一个概念，不预设学生已会。
2. 展示相应的分步图示或注册理论演示，允许回放、预测、再解释和换例子。
3. 在对话里给出一个与刚学内容对应的问题，学生直接在题目下回答。
4. 提交后显示“已保存”“评价中”和真实评价结果。未理解时围绕同一目标补讲；达到本活动要求后，由服务端返回下一步。
5. 题目、学生答案、课件版本、反馈与保存回执始终可以回看。进入实践仍需 TheoryMastered 和当前课时/活动授权。
6. 本课所有要求完成后，由现有课时 owner 确认，再由项目生命周期 owner 幂等对齐；前端显示下一课，不自行判定完成。

不要求所有问题都成为正式 mastery 考核。普通检查使用表达/形成性评价，正式考核沿原有题目和掌握度 owner；“看完”和“答过”都不直接等于掌握。

## 第一批：问答与保存连通，修复明确阻塞

### A. 每个 check 活动有明确的可作答入口（I01/I02）

- 按冻结活动的 evidence 类型分发：mastery 使用现有正式考核；session_response 使用开放问题与表达评价。保留权威事实来源，不另建问答完成状态库。
- 模型只能建议问题。服务端签发稳定问题实例/展示记录，关联 projectId、planId、revision、session、activity 和目标；问题正文、实例及学生答案能够回读。
- 动态生成失败时明确失败并允许重试；可使用已审核、范围匹配的现有问题，不能静默伪造“动态出题成功”。
- 扩展已有 `tutor.propose_lesson_activity` 的活动投影时遵守冻结能力版本；不通过改标题、放宽角色或改旧 binding hash 扩权。
- 学生点击题卡“提交”后，适配器调用既有 `submitLessonEvidence` 或正式答题 owner，显示真实回执和评价；普通自由聊天仍保持聊天语义。
- 用原有提交/判题事实构建只读历史投影，不依赖组件临时状态。历史正式答案只对已作答题释放，不能泄露待答题答案。
- 雷霆战机正式检查与光学采用一致的自动呈现原则，不再因为缺少 zero-base teachingMode 而只能手动启动。

主要落点：`LessonTeachingWorkspace`、`LessonAssessmentCard`、题目块及 `TutorPage` 提交适配器；`TutorLessonAssessmentService`、`LearningPlanService`、`WorksLearningEvidenceService` 与对应只读投影。

验收：两模板每课 check 都有明确问题/任务与提交入口；无需把答案复制进侧栏。刷新、切课后可回看原题、自己的答案和解析；错答和求助不替换待答题，重试不重复写入。

### B. 补讲与继续学习分开（I03）

- “再解释一下/看一个例子”明确指向学生正在看的课件实例及概念。客户端标识只是上下文，服务端重新校验归属。
- 保留普通继续教学的去重规则；显式补讲可针对已展示概念生成有来源的新示例，不要求先学完剩余概念。
- 补讲不重复增加教学完成事实，不修改掌握度；新增内容保留父版本/来源/用途，历史内容保留。
- 难懂反馈保存成功后提供对应补讲；科学/渲染问题形成可追踪修订或重试入口，不把保存标签说成已经修复。

主要落点：`LessonCoursewareCard`、课件工具 schema、`createCoursewareActivityPort`、`CoursewareService.capture/feedback`。

验收：A 已看完、B 未学时可以重新学 A；选择历史课件后得到针对该课件的例子；普通继续仍优先未学目标；无额外 mastery 写入。

### C. 课件故障按实例隔离（I04）

- 将全局 blockedReason 拆为单个课件不可用原因和当前活动不可继续原因。
- 历史课件失效不阻塞已核验有效的当前课件。缺少有效课件时始终保留重新准备入口，实际生成继续走授权/来源检查。
- 当前必需内容确实不可核验时，明确说明缺什么，不假装可继续；来源撤权仍立即生效。

主要落点：`TutorCoursewareService.read/position`、课件返回合同、`LessonCoursewareCard`。

验收：旧来源失效 + 新课件有效时可继续；当前来源撤权时不能确认；来源服务故障后能重试恢复，学习记录不丢失。

## 第二批：演示与问答衔接，记录持续可见

- 光学先使用已注册的只读理论预览，依据当前冻结授权恢复正确的工具投影；理论示意不开放正式实验参数写入或观测证据。
- 新增波幅叠加/相位或战机坐标/碰撞演示时，使用受控组件与版本化参数合同。模型选择组件与文案，不输出任意 HTML/JS。
- 每个演示配置观察任务、预测或解释问题；问题反馈与演示变量对应，避免只生成装饰性流程图。
- 保持中间对话的教学内容和原记录可回看，侧栏提供汇总与检索，不再让侧栏成为答题的必经入口。保持既有产品导航。
- 正式考核、表达评价和实验观察的“下一步”统一读取服务端当前活动及 blockers。部分提交成功但评价/对齐失败时，从已保存回执恢复，不让学生重做整题。

验收：首次进入能看见正确演示；回放、暂停、全屏和移动端正常；回答、反馈、实验观察与原课件的关系明确；历史回放不产生新的学习事实。

## 第三批：把课件库变成可复用的内容资产

- 先为关键概念选少量高质量课件，逐项检查科学性、教学适配、渲染、隐私和来源许可，再通过 Admin 发布。82 个 candidate 不能批量直接标为 published。
- 正确保存 explain/review/demonstrate/remediate 用途，避免检索用途与候选固定用途不一致。
- 先检索当前课程版本、目标、用途和知识库权限均匹配的资产；适合则复用，不适合才改编/生成。每次引用保留实际版本 ID 和来源。
- 雷霆战机通过新课程版本接入显式 teachingSpec 与相应来源授权；已冻结项目若需迁移，制定明确迁移入口和兼容规则，不能读时静默获得新授权。
- 反馈关联原版本，新修订作为新版本审核发布；学生原学习记录仍指向原版本。

验收：第二个授权项目确实复用同一已发布版本；未授权项目不可检索/使用；撤回版本不可继续使用；改编有来源与父版本链，不复制学生私有回答到公共资产。
