# 教学编排与学生对话界面

## Admin：把配置变成教学安排

截图红框内的步骤说明、统计、原始角色 ID、模型 ID、Skill 长列表和运行提示同时出现，且与下方导师检查器重复。即使排版换成卡片，也仍然难以判断“谁教哪课、缺什么、如何生效”。

建议在现有教学编排台内调整为：

```text
光学探究 · 课程版本／团队版本           绑定已启用 · 教学合同待完善
缺少：16 课完成规则、逐课方法、教材授权    [查看并处理]
────────────────────────────────────────────────────
课程导师        第 1–16 课课表                 选中课时编辑器
总导师          当前主讲／协作／完成规则       目标与固定开场
概念教练        每行明确已配置或待完善        主讲与活动协作
实验向导        支持按课时选择编辑            教学方法与授权资料
评审导师                                     学生产物与完成规则
────────────────────────────────────────────────────
草稿差异 → 检查问题 → 试点／发布 → 启用及回读
高级诊断：版本 ID、hash、原始 JSON、历史恢复
```

- 顶部仅显示课程、团队、真实状态和下一项阻断原因。分别展示“团队已发布”“绑定已启用”“课程可执行”；旧 v2 当前只能确认前两项。
- 删除重复原始角色列表；技术 ID 和 hash 收入高级诊断。技能以可理解的教学方法标签展示，技术 ID 可在详情中复制。
- 现有右侧检查器从“只读某位导师”扩展为“编辑选中课时”；内部提供主讲、协作、开场、能力和完成规则，成员能力保持只读快照。
- 点击每课“编辑”即可改课程草稿；“添加导师”选择已有助手或进入现有助手配置。发布课程不能只保存一份未被消费的本地列表。
- “启途智学助手”放在接待说明中，不混入正式导师成员列表，也不出现在课时主讲／协作选择器中；服务端同样校验。
- 只显示真实就绪状态。当前团队版本发布已同步运行 Agent 和委派路由，不再沿用“只有助手、没有 Agent 时对话继续”的笼统旧提示。读取失败则明确显示未核验。
- 明确课程版本与团队版本属于不同序列，避免“团队 v5”被理解为“逐课课程 v5”。

课时／课程已发布时显示只读和“基于此版本编辑草稿”。修改团队成员、Skill、模型或授权范围时提示需要新团队／课程绑定版本；不能原地覆盖冻结快照。

## 学生：先看到要做什么

正式第 1 课的开场示例：

> **第 1 / 16 课 · 光的宏观现象与观察指标**  
> 本课导师：光学原理与概念教练
>
> 水中的筷子看起来弯了，镜子里的筷子却保持笔直。先不急着解释：你分别看到了什么？
>
> 这一课我们会把“看到的现象”和“对原因的猜想”分开，完成一张观察表。
>
> **从水中筷子开始**　**从镜中成像开始**　**说说我的观察**

这是拟定的课程文案，不是已发布内容。正式开场从模板 session 的版本化配置读取；不由模型每次随机改写，不要求学生发送“请结合我已有证据开展教学”之类系统提示词。

| 页面区域 | 展示方式 |
| --- | --- |
| 开场任务卡 | 课次、主题、真实主讲、情境、一项学习产物、一个首要动作；次要入口不抢主任务 |
| 公开选项 | 短标题与必要情境，不展示内部指令；提交动作绑定服务端稳定实例及当前范围 |
| 教学回复 | 以当前活动的讲解／例子／板书／练习为主，按需折叠细节，不把所有组件一次堆上来 |
| 项目进度 | 完成课数／总课数、当前课和活动、缺失证据、下一动作；阶段只是课程分组与门禁背景 |
| 团队智能体 | 当前主讲、实际协作任务、总导师协调、其他成员待命；区分生成中、已产出候选、等待评价、失败及重试 |

团队状态来自真实 run／task／owner 回执。候选生成成功不能显示“学习已完成”；页面不能因成员存在就给所有导师标记运行中。协作不可用时保留已接受证据并提示当前受影响任务。

## 固定开场、动态课件与资产化复用

课件和题目基于**“零基础初学者友好”**的认知建构逻辑，以“通俗理论讲解 → 动态课件演示 → 随堂出题检查 → 证据推进完成”的四步闭环运行。课件资产优先复用已有高分模板，支持按需改编与现场生成，详见 [05 干涉与衍射课程](./05-interference-diffraction-curriculum.md)。

- **固定的是教学意图与结构**：本课情境、目标、首个问题／动作、预期证据以及必要提示，随课程版本冻结。
- **动态的是教学内容与节奏**：主讲结合当前活动、教材授权与学生已接受证据，推荐已有课件资产，或生成本轮 BoardBlock、Mermaid、KaTeX、同目标例子或检查题。
- **课件资产化流转**：每个生成的优质动态课件赋予唯一 `assetId` 沉淀入库，支持跨项目、跨课时检索复用与衍生微调（Adapt），不再是单次会话临时抛弃的消耗品。
- **分阶段提示词策略**：
  - **理论讲授与课件演示期**：放行概念解释、生活比喻、图文定义与完整演示，不触发答案泄露拦截；
  - **随堂检查期**：严格开启防泄露守卫（`safety.answer_leak.guard`），仅提供阶梯提示（Hint），由服务端考核 owner 校验作答。
- 切换到下一课才生成该课开场；刷新、断线重连和切换导师不重复插入。以项目、plan revision、learning session 和开场版本建立幂等身份。
- 恢复会话时回到原有当前活动、待答题和已保存观察，提示尚未完成的动作；不从头重讲固定欢迎语。
- 板书翻页只改变展示，学生答题／记录产生证据，owner 接受结果后策略才决定下一步。
- 理论门禁前只使用获准的低风险示意，不把实践仿真提前变成正式实践任务。

针对目前学生端出现的聊天流底部冗余卡片与交互粗糙问题：

1. **聊天流纯净化**：
   - 彻底从 [ChatThread.tsx](../../../../apps/student-center/features/tutor/components/ChatThread.tsx) 消息列表底部移除 `{learningActivity}`。
   - 对话主视口只保留对话气泡、动态板书/实验仿真、输入框及底部灵感胶囊，消除“对话结束后粘滞在末尾的大灰块/粉红块”。
2. **课时进度与证据提交通道移入抽屉/上下文侧栏**：
   - 课时任务、证据提交与作品申请统一在右侧 `qitu-tutor-context-sidebar`（已挂载的 [CurrentLessonCard.tsx](../../../../apps/student-center/features/tutor/components/CurrentLessonCard.tsx)）中操作，移动端折叠进侧边抽屉。
3. **修正红色考核区域**：
   - 当前 `LessonAssessmentCard` 对所有当前课时挂载，且复用错误提示样式；接口在非理论考核课返回“本课通过学习产物或探究证据完成”。这是任务适用性，不是错误。
   - 由服务端投影本活动可用动作及原因：只有当前课时进入“理论考核（check）”阶段才激活考核卡；观察活动显示观察表，设计活动显示假设／方案提交，报告与反思显示相应作品入口。前端据此渲染，接口再次校验，不能仅凭课号推断。真正的权限、范围变化和网络失败才使用错误样式。
4. **选项与提交交互升级（基于 Stitch 设计系统）**：
   - 选项改为微动效卡片，支持直接单选触发，消除多余的“确认提交”按钮。
   - 底部反馈文字重构为悬浮胶囊：`💡 听懂了`、`🤔 有点绕`、`🆘 求提示`，实时调节导师后续输出阶梯。

## 会话历史：一个项目连续学习

现在历史列表直接合并项目会话和探索会话；立项前后可出现两个相似标题，列表仍以宏观“项目已确认”为主要标识。导师交接也缺少课时语境。

1. 使用既有 `projects.sourceExplorationId` 精确关联，立项后在一个项目学习条目下折叠显示前期探索；不按标题去重，不物理合并或重写原会话。
2. 主条目显示项目标题、当前第几课、真实已完成课数与最后互动时间；展开可查看课时记录及前期探索。
3. 课时交接写入可恢复的系统事件，例如“进入第 3 课，由概念教练主讲”；保留各轮真实作者。标签显示主讲／协作等中文职责，不把所有消息标作 leader。
4. 同模板的独立探索保留为不同记录；重复点击、刷新和重试复用既有幂等规则，不能不断创建新项目或空白探索。
5. 删除聊天仍是永久删除所选会话内容；删除项目仍走项目生命周期 owner。折叠展示不改变删除范围，也不把“隐藏”冒充删除。永久删除内容不能由历史缓存重新恢复；仍有合法用途的课程证据和审计遵循原 owner 规则。

所有修改保留 loading、empty、权限失败、断网、重试和只读状态；移动端按现有侧栏交互收纳，键盘和 reduced-motion 继续可用。公开页面不展示 binding hash、原始 Skill 长列表或后端实现说明。
