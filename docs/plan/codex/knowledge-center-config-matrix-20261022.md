# 知识中心配置与助手绑定矩阵方案

状态：2026-10-22 用户已确认实施。接口、配置抽屉、绑定矩阵与远程隔离验证已实现；实际发布状态与测试边界见[实施记录](../../admin/knowledge-matrix-release-20261022.md)。本文件保留设计依据，不把源码或配置存在等同于生产资源可读。

## 目标与范围

知识中心集中回答两个问题：平台配置了哪些知识库，每个助手被允许使用哪些知识库。

保留 `/admin/settings/knowledge` 入口和“知识库 / 知识引擎”两个页签。知识库页采用上方配置、下方矩阵的布局；知识引擎页维护可复用的连接、模型和默认参数。

主流程移除文件树、全文阅读器和库内重复的助手编辑入口。远端文件在原服务管理。本地库保留必要的素材导入、来源同步和索引维护，收进配置抽屉的高级区，继续调用已有服务。

2026-10-23 先补回已有文件查看；按用户后续反馈，进一步将查看和编辑合并为卡片上的单一「查看与编辑」入口，在页内详情工作区通过 DeepTutor 风格的页签切换文件、导入、来源、索引版本和设置。主列表的助手授权矩阵保留，详情不再使用分离的预览弹窗与配置抽屉。当前方案与验证记录见[知识中心](../../admin/knowledge-center.md)。

本次只调整知识配置与授权管理，不修改课程、团队排期、项目状态、掌握度或教学门禁。现有知识记录和原文件保留。

## 已核对的现状

- `KnowledgeLibrary.tsx` 已在列表下方放置绑定面板，但它依赖选中一个库，只能逐库查看助手。
- `LibraryDetail.tsx` 还有文件工作区和“AI 助手”编辑页签，创建弹窗也支持助手绑定，形成多个编辑位置。
- 逐库授权已存于 `knowledge_base_agent_bindings`，全局检索配置和引擎配置由现有 platform configuration owner 维护。
- `saveBaseBindings` 当前删除指定库的全部绑定再重写；矩阵不能只提交可见助手，否则会丢失其他 Agent 或权限模式的记录。
- 统一检索按逐库绑定过滤。IMA 的部分当前授权解析仍按引擎白名单返回库，需要让 MCP 与统一检索使用相同的逐库授权限制。
- 已诊断的两个生产 IMA 连接保存了当前上游拒绝的旧 ID；当前官方列库返回的 ID 可用于目录和搜索。尚无证据确定 ID 差异最初如何产生，不按名称推断资源等价。
- 页面“可用”取自旧 `build_state`，目录失败不会自动反映到该标签；目录错误还被替换为“来源暂不提供目录”。

## 页面方案

### 上方知识库配置

列表显示库名、来源与引擎、启用状态、连接或索引状态、最近检查时间和已绑定助手数量。读取失败时数量显示“未知”，不显示 0。

每个库提供“配置”“检查连接”“停用 / 启用”。远端库另有“重新关联”“前往原服务”；仅在原服务提供合法入口时展示外链。删除仍沿用软删除和影响提示。

配置抽屉按类型展示：

| 类型   | 配置内容                                           | 验证依据                   |
| ------ | -------------------------------------------------- | -------------------------- |
| 远端库 | 引擎实例、账户范围、官方目录选择的远端库、只读能力 | 当前资源身份和实际读取接口 |
| 本地库 | 引擎实例、模型引用、来源、导入及索引参数           | 实际索引构建与检索检查     |

本地库高级维护不再默认打开文件阅读器。已创建库与成功上传、成功构建、成功检索分别展示。

### 下方助手绑定矩阵

行使用真实助手目录，列使用已配置的知识库。团队和课程角色不作为新的授权主体，继续引用真实助手 ID。

| 助手   | 光学教材 | 光学题库 | 物理选修二       |
| ------ | -------- | -------- | ---------------- |
| 助手 A | 已绑定   | 未绑定   | 已绑定，连接异常 |
| 助手 B | 未绑定   | 已绑定   | 未绑定           |

矩阵固定助手名称列和库名表头，支持搜索、单元格勾选、按行或列批量选择、保存变更、放弃草稿。首期不提供跨全部库的一键全授权。批量操作仅影响当前明确展示的范围，不修改过滤外的绑定。

手机端按选中的助手展示库清单，使用相同数据和保存合同。

单元格表达两个事实：绑定是否已保存，以及当前配置是否允许检索。未保存修改另加草稿标记。阻断原因直接显示为助手停用、检索关闭、连接异常或权限不足，不笼统标记“已生效”。

已有绑定即使遇到停用或异常也允许撤销。异常库可保存绑定意图，但显示“已绑定，暂不可用”。目录不完整或权限读取失败时阻止受影响范围的新增与批量保存，保留已读数据和草稿。

创建库时专注配置资源；创建成功后定位矩阵对应列。库内旧助手页签改为跳转矩阵的定位入口，不再维护另一份草稿。

## 授权与保存

矩阵是逐库助手授权的主要编辑入口，继续使用现有绑定表。引擎凭证和默认配置继续由现有配置 owner 管理。

实际访问由以下条件共同决定：

1. 当前库启用且连接或索引可用。
2. 当前助手启用、逐库绑定允许、检索总开关和工具权限允许。
3. 当前用户具备对象权限；正式项目还受冻结 grant、实际课时角色和工具版本约束。
4. 上游账户或 MCP 服务当前仍允许访问该资源。

矩阵不能单独宣称某个正式项目已获授权。新增绑定不扩大旧项目冻结范围，当前撤权在后续工具调用及结果返回前复核。列库、搜索、列文档和读文档都执行相同的库范围；读取原文还检查有期限的 provenance。

旧 MCP 授权保留为工具执行条件，不能成为跳过矩阵的另一条访问路径。不同引擎实例按实际连接解析，不继续依靠固定 `ima-main` 或库名推断授权。

拟新增两个 Admin 接口，具体合同在实施时写入共享 contracts：

- `GET /api/v1/admin/knowledge/binding-matrix`：聚合助手、库、绑定、逐库修订和阻断原因，支持分页或限定库范围，并明确返回目录是否完整。
- `PATCH /api/v1/admin/knowledge/binding-matrix`：只接收变化的助手与库绑定项、预期修订和幂等键，返回逐库结果。

保存按知识库分组，每组事务内验证修订、写入变化项和审计。跨库允许部分成功，前端逐项展示。并发冲突只刷新受影响库，保留其他草稿。

数据写入仍归原知识模块 owner。新增聚合层不得另建授权表；不直接转发不完整的全数组到旧替换接口。先提供增量写入能力，再让旧编辑入口复用或跳转，保留非本次范围的 Agent 和权限模式。

保存后由服务端回读确认，再清除成功项草稿。回读失败显示“提交已返回，状态待确认”，使用同一幂等键和请求核验，不能展示全部成功。读取响应按请求身份判断，旧响应不得覆盖新筛选、新草稿或已保存状态。

检索总开关在本页可见，保持显式控制。沿用现有 owner 对助手检索绑定的维护语义，不自动开启引擎、MCP 或被停用的助手。

## IMA 连接修复

1. 重新读取当前账户的官方库目录，由管理员明确选择资源；不按名称、ID 前缀或旧缓存自动替换。
2. 用选定 ID 验证资源身份和目录访问。检索能力用独立只读探测验证，原文能力只在成功读取样本后标记通过。
3. 在现有连接 owner 中增加重连命令，携带旧修订、预检关联信息和幂等键；提交时重新核验同一实例与资源，防止预检后配置变化。
4. 保留本地库 ID 与助手绑定，原子更新经确认的连接版本并使旧证据缓存失效。失败保留原记录并显示错误，不记录虚假的新成功。
5. 远端身份变化不重写项目冻结快照或 grant。无法证明与旧冻结资源一致时，旧项目继续拒绝访问，另走受治理的新版本或恢复流程。

把上游“无效知识库 ID”归为稳定的“关联库 ID 无效，请重新关联”诊断。凭证错误、超时、限流和未提供能力分别处理，不向浏览器暴露原始异常或密钥。

列库分页采用实际接口约束。目前只读复核显示 `search_knowledge_base` 的 limit 上限为 20，需同步收紧请求校验、运行时与文档，不能继续宣称该接口支持 50。

## 实施顺序与交付

| 步骤                  | 交付内容                                     | 通过条件                                         |
| --------------------- | -------------------------------------------- | ------------------------------------------------ |
| 1. 评审与文档         | 确认本方案，更新知识中心和平台治理文档       | 配置、矩阵及本地维护边界明确，导航变化获得评审   |
| 2. 连接状态与重连     | 稳定错误码、当前状态、重连合同、IMA 分页约束 | 旧 ID 明确失败，当前选定资源验证通过，失败可恢复 |
| 3. 矩阵后端与统一授权 | 聚合读取、增量 PATCH、共享权限解析           | 局部修改保留其他绑定，所有读取路径遵守逐库撤权   |
| 4. 页面调整           | 上方配置区、下方矩阵、配置抽屉和移动端清单   | 单库与多库编辑可回读，重复编辑入口退出           |
| 5. 迁移核对与验收     | 旧绑定对账、重连影响记录、行为测试和发布说明 | 无隐式扩权，真实检索与原文分别验收               |

现有表能承担主体数据，优先不增加业务表。连接版本或检查回执若确需字段，再做小范围增量迁移，并提供降级说明。

部署与生产重连单独记录。源码存在、接口测试通过、配置已保存、生产真实请求成功分别作为证据，不能互相替代。

## 验收清单

- 首屏可以直接看清助手与库的多对多关系，无需逐库点击。
- 页面覆盖 loading、empty、error、离线和权限失败；目录失败不冒充空目录，未知数量不显示 0。
- 单格、行列批量、过滤和分页只修改明确选择的对象；停用对象仍可撤销绑定。
- 保存支持幂等重放、并发冲突、部分成功和回读失败，成功项与待确认项分别展示。
- 矩阵未展示的 runtime Agent、Partner、权限模式和未知历史记录保持原样。
- 统一检索和 IMA 四个只读工具在解绑后都不能继续访问；缓存引用、跨项目引用和进行中的请求结果也要复核。
- 当前连接成功不会扩大旧项目冻结 grant；连接身份变更导致旧引用失效，不能按同名库授予新语义。
- IMA 旧 ID 显示可操作错误；新 ID 的目录、检索、原文能力分别通过实际调用验证。
- 本地导入和构建仍由已有 owner 执行，失败不替换已有有效索引。
- 合同包和依赖按顺序构建后执行针对性 API 行为测试、Admin 类型检查与桌面/移动端验证；生产登录与真实外部调用另记结果。
