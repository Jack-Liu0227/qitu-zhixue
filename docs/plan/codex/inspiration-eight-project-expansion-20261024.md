# 灵感空间新增八类项目、团队与模板计划

> 状态：in_progress / 用户要求继续实施，2026-10-24。实施状态与验证见[实施 Issue](../../issues/20261024-inspiration-eight-projects.md)；规划表中的数量不代表线上资源已经创建。

本计划按用户“先制定计划”的要求编写。基线来自本地源码及既有上线记录；未对线上配置进行本轮回读。以下新增资源名称、slug 和数量均为拟议配置，不代表资源已经存在。

## 1. 目标与交付范围

在现有灵感空间中新增八个不同类别的项目，对应八个 Admin AI 教学团队和八个独立版本化项目模板。全部就绪后，目标可选目录为原有两项加新增八项，共十项。

“对应的模板库”落实为现有 Admin 模板库中的八个新模板，每个都有自己的课程内容、版本、排期、评价标准和教学绑定。团队在现有团队管理中维护。知识资料按各项目实际需要建立或授权，知识库数量不与团队数量机械对应。

首版暂按 11–15 岁、零基础可进入、每项目 8 × 60 分钟设计，共 64 个新课时。年龄与课时是设计假设，内容审核后再冻结；植物观察项目另需跨日记录，八课时不表示八小时内完成。

交付包括：

- 八套项目选题、驱动问题、理论准备目标、逐课任务与最终作品要求。
- 八个领域教学团队。每队三个有明确职责的助手席位，预计共 24 个领域助手配置。
- 八个模板首版、八套课时排期，以及每课实际团队、主讲助手和按需协作成员的绑定。
- 各类作品的证据与 rubric 配置、正式概念检查、错误补救和自主评价路径。
- 灵感空间卡片与详情所需的类别、简介、年龄、课时、作品、材料和来源说明。
- 可恢复、幂等的配置步骤及逐项验收记录。

## 3. 八类项目与最终作品

| 编号 | 类别 | 项目与驱动问题 | 最终作品 | 必须由学生产生的关键证据 |
| --- | --- | --- | --- | --- |
| P1 | 生命科学 | **一颗种子的七天日记**：在可控条件下，供水条件不同的种子会出现什么差异？ | 带原始记录的种子观察档案与条件比较报告 | 学生提出的预测、变量表、带日期的观察、比较结果、结论边界 |
| P2 | 环境与可持续 | **让一周的包装少一点**：怎样减少日常包装，并用一致的记录证明变化？ | 包装审计表、减量行动方案与前后比较说明 | 分类口径、基线记录、实施记录、差异与替代解释 |
| P3 | 应用数学与数据 | **给图书角做一次数据诊断**：借阅数据能支持哪些藏书调整建议？ | 数据图表、分析说明与图书角改进建议 | 数据字典、清洗记录、分母与计算、图表选择、反例检查 |
| P4 | 公共服务与设计 | **让第一次来的人也能找到路**：怎样改进一个虚拟校园的导览？ | 导览草图、标识方案与任务测试记录 | 需求约束、初稿、按固定任务记录的查找过程、修改前后差异 |
| P5 | 历史与文化 | **给一件老物件办微型展览**：我们能根据哪些材料讲清它的来历与用途？ | 微展览策划、展签与来源清单 | 来源比较、时间线、史实与推测标记、展签修订理由 |
| P6 | 语文与叙事 | **一个选择，两种结局**：怎样让读者理解角色的选择及其后果？ | 双结局短篇、角色关系图与修订说明 | 学生提纲、关键场景初稿、因果解释、具体修订及反思 |
| P7 | 媒介与信息素养 | **为一条流传说法做核验**：一条说法到什么程度才值得相信？ | 主张核验卡、证据对照表与核验短文 | 主张拆解、原始来源追溯、独立来源比较、支持/不足/未核验判定 |
| P8 | 经济与创业启蒙 | **用一百元设计一次文创试售**：怎样让一份虚拟试售预算经得起质疑？ | 虚拟产品方案、成本预算表与情景分析 | 成本假设、单件计算、收支核对、销量变化分析、方案修订 |

八个项目分别侧重生物观察、环境行动、数据分析、服务设计、历史解释、文学创作、信息核验和资源配置。它们使用不同的概念目标、任务、证据和 rubric；共享的是既有教学机制。

P1 只使用常见种子、清水和安全容器，不培养未知微生物，不使用药剂，不要求品尝。P2 只记录干净包装，不翻找垃圾。P4 默认使用虚拟地图与模拟任务，不要求独自外出。P8 全程使用虚拟预算，不要求真实支付、售卖或接触陌生人。

## 4. 团队与模板对应关系

每队首版设置三个领域助手：探究与概念导师为负责人，方法与作品导师负责实践支持，质询与修订导师负责提出评价候选和修改建议。作品正式评价仍由 Works 及平台自主学习策略处理，团队助手没有通过作品或改变阶段的权限。

| 项目 | 新团队名称 | 三个领域职责 | 拟议模板 slug |
| --- | --- | --- | --- |
| P1 | 种子与生命探究团队 | 生命现象教练 / 观察方法向导 / 证据解释教练 | `seed-observation-inquiry` |
| P2 | 绿色生活行动团队 | 可持续探究教练 / 行动记录向导 / 效果复核教练 | `packaging-reduction-action` |
| P3 | 数据与数学探究团队 | 统计概念教练 / 数据分析向导 / 图表质询教练 | `library-data-inquiry` |
| P4 | 公共导览设计团队 | 用户需求教练 / 导览设计向导 / 可用性复核教练 | `inclusive-wayfinding-design` |
| P5 | 历史文化策展团队 | 历史问题教练 / 史料与策展向导 / 史实核对教练 | `object-history-exhibition` |
| P6 | 叙事创作团队 | 阅读与叙事教练 / 写作修订向导 / 文本反馈教练 | `choice-story-studio` |
| P7 | 信息核验团队 | 主张拆解教练 / 来源核验向导 / 证据质询教练 | `claim-verification-lab` |

slug 是建议的资源查找键，不是已存在的 templateId、teamId 或 assistantId。创建和回读后记录真实 ID，再配置稳定成员 slot、每课主讲者、协作触发条件及实际 roleMap。不得按中文名称或 ID 前缀推测运行授权。

每课默认只有一个主讲。协作导师按学生请求或证据事件触发，避免三个助手同时输出重复解释。领域助手分别编写提示词、问题示例和评价约束，不套用光学或编程指令。

候选教学技能复用现有 canonical ID，不新增同职责的技能副本：

- 基础教学考虑 `tutor-guided-learning`、`pbl-understanding-coach`、`pbl-concept-probe`。
- 展示与作品支持考虑 `pbl-dynamic-lesson`、`pbl-visual-explainer`、`pbl-artifact-revision`、`pbl-reflection-coach`。
- P1 按实际任务考虑 `pbl-hypothesis-coach`、`pbl-experiment-design`、`pbl-cer-coach`；P3 考虑 `pbl-data-literacy`；P5/P7 考虑 `pbl-source-literacy`、`pbl-ai-output-audit`。

以上仅为源码中可见的方法候选。执行时先读取当前运行时目录，验证 teaching、ready、published 及真实 digest，再逐课选择必需项。Admin 编排技能不绑定学生助手。模型只能使用 Admin 目录中明确的 `(modelProviderId, modelId)`，本计划不预选裸模型名或扩大知识授权。

## 5. 首版逐课安排

开课前沿用探索草稿与意图/计划确认流程。学生确认后才创建正式项目并冻结版本和教学安排，随后开始正式第 1 课。预览、阅读推荐卡或助手自动开场不算完成第 1 课。

正式课时按四阶段兼容合同组织：第 1 课明确问题，第 2–3 课建立理论准备，第 4–7 课实践、形成作品并修订，第 8 课解释、反思与归档。每项目单独定义 TheoryMastered 所需概念与正式检查。课号不能自动触发掌握或作品通过。

| 项目 | 第 1 课：问题与任务 | 第 2 课：基础概念 | 第 3 课：方法与准备检查 | 第 4 课：首轮实践 |
| --- | --- | --- | --- | --- |
| P1 | 明确种子、比较条件和预测 | 发芽观察指标与条件 | 控制变量、重复观察及正式检查 | 设置安全的条件比较并记录起点 |
| P2 | 确定包装范围与行动目标 | 减量、重复使用及分类口径 | 基线、比较周期与正式检查 | 形成基线记录并选择一个行动 |
| P3 | 阅读脱敏借阅数据，提出问题 | 类别、频数、比例与分母 | 缺失值、图表选择及正式检查 | 清洗数据并计算首组指标 |
| P4 | 识别初次到访者的查找任务 | 信息层级与标识一致性 | 路线约束、测试方法及正式检查 | 绘制导览和标识初稿 |
| P5 | 选择有授权资料的老物件 | 史料类型、时间与出处 | 事实、推测、来源比较及正式检查 | 制作有引用的物件证据卡 |
| P6 | 确定角色、冲突与关键选择 | 视角、动机与因果 | 场景表达、叙事连贯及正式检查 | 写出关键选择场景 |
| P7 | 选择低风险、可核验的说法 | 主张、证据与原始来源 | 来源独立性、核验状态及正式检查 | 追溯第一条证据链 |
| P8 | 定义虚拟产品和预算约束 | 单价、数量、成本与收入 | 固定/变动成本、假设及正式检查 | 编制第一版成本表 |

| 项目 | 第 5 课：扩展与核对 | 第 6 课：分析与改进 | 第 7 课：作品提交与修订 | 第 8 课：解释与反思 |
| --- | --- | --- | --- | --- |
| P1 | 按日观察，处理缺测 | 比较现象并解释替代原因 | 提交观察档案，按反馈修订结论 | 用记录答辩，说明样本与观察边界 |
| P2 | 实施行动并连续记录 | 对比变化，核对口径是否一致 | 提交行动报告并修订建议 | 说明证据支持的变化与局限 |
| P3 | 制作两种图表并比较 | 检查异常、分母和替代解释 | 提交数据建议并回应质疑 | 用数据解释一项决策及其限制 |
| P4 | 按查找任务走读虚拟地图 | 记录歧义并修改标识 | 提交导览方案与前后对照 | 解释设计依据和未覆盖的使用者 |
| P5 | 形成时间线，比较材料冲突 | 组织展览叙事并标明不确定处 | 提交展签、来源和策展方案 | 回答史料质询，区分史实与推断 |
| P6 | 分别写出两种后果 | 核对动机、伏笔和结局因果 | 提交双结局作品与修订说明 | 引用自己的文本解释写作选择 |
| P7 | 对照独立来源与上下文 | 检查反证、缺失与适用范围 | 提交核验卡并收紧结论 | 说明何种新证据会改变判断 |
| P8 | 设计定价及销量假设 | 比较不同销量下的收支 | 提交预算与方案，修订不一致项 | 解释关键假设与方案风险 |

每课都需另行完成目标、时间块、开场、讲解/展示、学生尝试、证据要求、反馈、补救与完成条件的合同编写。上述表格是编写任务清单，不能直接代替可运行的 ProjectTemplateSpec。

## 6. 内容、展示与证据标准

每模板至少完成一套冻结的概念准备目标、对应正式检查、示例与反例、同目标补救、逐课板书要求、最终 rubric 及修订规则。正式检查接入现有题实例、判分和 mastery owner；普通对话、看过课件或 AI 自述不算掌握。

展示使用既有闭合 TutorReplyBlock、BoardBlock、Mermaid 和按需 KaTeX。P1 展示变量与观察看板；P2 展示行动比较表；P3 展示数据与图表解释；P4 展示导览拓扑；P5 展示时间线与来源关系；P6 展示角色和情节分支；P7 展示证据链；P8 展示预算表与计算。涉及未支持的图表或导览编辑时，首版使用既有安全板书或作品附件合同，不承诺已经存在的新编辑器。

按现有 auto-launch opening turn 机制提供一个与项目有关的启发问题。后续由“学生回答/操作产生证据，服务端策略选择下一教学动作”的双循环驱动，正式待答题不被助手求助或重复开场覆盖。

| 项目 | rubric 的主要判断项 | 明确的证据边界 |
| --- | --- | --- |
| P1 | 记录可追溯、变量控制、比较合理、结论有限度 | 提供的示例数据标为练习材料，不能当作学生实际观察；不因样本很少就下普遍因果结论 |
| P2 | 记录口径、行动可行性、前后比较、反思 | 包装数量变化不直接换算为减碳成效；无来源时不生成碳排放效果数字 |
| P3 | 计算、图表、解释与限制 | 使用授权的脱敏汇总或明确标识的合成数据，不采集同学姓名、借阅隐私和个人画像 |
| P4 | 任务匹配、标识一致性、测试记录、修订依据 | AI 角色走读必须标明模拟，不能称为真实用户测试，也不要求找到校外测试者 |
| P5 | 史料出处、事实准确性、不确定性、展览表达 | AI 推测与缺失资料显式标记；不编造年代、引文、页码或人物经历 |
| P6 | 动机与因果、具体表达、两种结局的合理性、修订解释 | 不按情感倾向给学生贴标签；AI 代写段落不算学生写作证据，需学生解释和实际修订 |
| P7 | 主张拆解、来源追溯、独立核对、结论校准 | 来源不足时允许得出“未核验”，但必须提交真实核验过程；不把无来源判断当核验成功 |
| P8 | 预算一致性、假设透明、情景比较、调整理由 | 金额与销量是虚拟设定，不声称市场收益，不要求真实交易 |

课程素材先形成授权与来源清单，再通过现有内容/课件 owner 审核。没有当前可用 IMA grant 时，优先使用已审核、冻结到模板或课件资产中的小型材料包。项目明确要求实时检索且缺授权时阻止相应能力启用，不伪装检索成功。

知识授权取冻结项目 grant、当前 Admin 全局授权、助手/工具和对象权限的交集。新领域资料不扩大原有项目范围；知识库创建、资料入库、索引可用与真实检索成功分别验收。

## 7. 技术实施拆分

### A. 核实目录与开立实施 Issue

只读获取当前团队、助手、模板版本、active 绑定、模型 pair、运行时技能发布状态和知识授权。记录原两项目的实际 ID、版本、binding 和 hash。为跨领域作品证据适配开立有边界的 Issue，列明范围和回归场景；不借本任务进行大范围重构。

检查现有部署、运维及验证说明中“目录恰好两项”的断言，将新目录扩展验收独立出来。保留历史命令与历史回执的原意，新命令只处理本次新增资源。

### B. 打通通用作品证据与自主评价

先做 P6 叙事写作和 P7 信息核验两类内容的隔离样板，验证非代码、非实验报告的作品能沿既有 owner 完成提交、评价、修订、课时收口和归档。

拟在现有合同中增加一个通用 rubric 作品证据档案及对应受注册门禁支持的映射。具体 canonical 字段和 ID 在该 Issue 的合同评审中确定，当前不把拟议标识当作已注册能力。优先复用现有 document/作品版本及 Works 回执，不增加作品库或学习状态库。

同步接线范围应包含 contracts 的解析与注册、门禁推导、模板 validator、团队/教学包编译、Works 作品评价与事实 materializer、Learning Plan 完成条件、项目阶段评估和最终归档。即使个别路径已有通用占位，也需核对其实际注册与生产者，不能仅凭字符串存在就使用。

保持 `TheoryMastered` 与全部历史 evidenceProfile 语义；新作品不伪装成实验报告，不回落到代码运行门禁。继续使用 `autonomous-learning.v1` 和 Admin `learning.evaluate` 用途策略，AI 只返回候选，服务端校验确切作品版本、正文摘要、目标与 rubric。故障时保存证据并允许重试。

### C. 编写八套课程与领域助手

每项目在现有 `services/api/src/modules/templates/content/` 下建立独立内容模块，通过实际 ProjectTemplateSpec 解析与校验。Theme、Session、课程角色及资料范围都进入同一版本化合同。每个源文件遵守 2500 行上限。

为每个理论目标登记相应正式检查与题实例映射，防止新项目落到光学题库或全局 fallback。模板生成器消费实际模板内容与 hash；生成结果需通过既有计划验证，不只给公共排期贴上新的版本 ID。

按当前发布目录给 24 个领域助手配置技能、受支持工具和 Admin 模型 pair，再组成八个团队。单轮管家计划若受动作数量限制，按项目拆批提交；批次之间使用真实回读 ID 与修订，不用未成功的前序引用。

### D. 保存模板与逐课教学安排

在现有 Admin 模板库中创建八个新模板及首版，分别使用独立 bootstrap identity、排期 profile 和内容 hash。逐课提交真实团队、助手及修订，交由既有 owner 自动保存冻结团队配置，编译、校验教学包并建立绑定。

生命周期遵循当前能力目录及原 owner 的真实前置条件。草稿、校验通过、试点可选、绑定 active 和正式发布分别回读；仅以配置校验通过不能宣称课程已发布。缺技能、模型、概念检查、作品门禁或必要来源时保留草稿并说明缺项。

新增写入使用稳定幂等键与修订校验。中断后复用已成功的模板、版本、助手和绑定，只重试失败项；不得按同名重新创建一套。运行时路由读取实际 frozen session/task，不能按团队名猜测权限。

### E. 接入灵感空间

沿用现有推荐列表、卡片、详情和“与AI搭档开始”的交互路径。为八类新 domain 补充正确的中文展示，并同步核查其他消费相同分类的页面；课时信息从冻结 active 教学安排投影，不能写死。

卡片与详情展示项目目标、作品、年龄、材料及跨日要求。分类先使用现有卡片标签和展示字段；若后续确需类别导航、搜索或分页等信息架构变化，另按产品文档评审处理。

目录增量从服务端读取，保留学校/平台范围权限、loading、empty、error、offline 与 permission-denied 状态。错误、断网、403 或回读失败不得改用 fixture 填充“成功”列表，学生读取也不能依赖管理员权限。

### F. 分批试点与验收

## 8. 验收清单与发布边界

- 配置数量：新增八个真实团队、八个模板首版、八个完整排期与八个有效教学绑定。助手按实际交付去重计数；团队保存、绑定 active 与真实 Team Run 成功分开记录。
- 内容完整：64 课均能追溯到课程目标、主讲助手、活动、学生证据、来源/材料及对应完成条件；不存在换标题后复用光学或编程内容的情况。
- 理论门禁：每项目正式检查都命中自己的目标和题库。答错进入同目标补救；第 3 课结束、点“下一课”或 AI 宣称理解都不能自动解锁实践。
- 作品链路：学生提交确切版本，服务端自动评价，反馈支持修订，修订使旧评价失效；最终答辩、反思及归档均有 owner 回执。全程无需教师审批。
- 权限与来源：跨学生、跨校、跨项目、跨课时/修订的证据和动作被拒绝；知识撤权即时收紧；来源不足明确未核验，无法访问的资料不被伪造引用。
- 幂等与恢复：重复配置、重复回答、重复提交、并发评价与网络中断不重复创建或错误覆盖；模型故障保留已保存正文并可恢复。
- 用户体验：十项卡片在桌面和移动端可读，详情、意图确认、开场、学习、退出恢复和最终归档连通；五类页面状态有真实验证。
- 历史回归：原干涉衍射和雷霆战机的模板、绑定及 hash 不被本次扩展改写；原有项目仍按自己的冻结配置运行。

验证先按依赖顺序构建 `@qitu/contracts`、`@qitu/database`、`@qitu/ai-client` 及实际依赖，再执行相关 API/应用检查。重点覆盖通用作品、模板/教学包、正式判分、课时推进、对象权限、幂等恢复和两个原项目回归。类型检查不能替代学生行为测试。

每个项目都需一次从首课至末课的隔离完整行为验证，并记录真实模型与知识读取的单独结果。跨日项目允许在隔离环境用明确标识的时序 fixture 验证恢复与证据合同，但不能冒充真实植物观察或实际减量效果。

配置验收后分批进入受治理试点；正式发布仍由原 template owner 验证所需证据。回退优先撤销新增项目的未完成教学安排，已可选项目按既有归档/停用 owner 退出新建目录，保留既有学生项目和冻结快照。上线前先验证停用对已有项目的影响，不删除历史证据。

## 9. 本轮计划产出与共存修改

本轮只新增本计划，并在 [方案入口](./README.md) 增加链接，没有执行资源配置、模型调用、发布或生产数据写入。检查范围是本地源码、已有文档与计划链接，不把规划检查写作运行验收。

验证口径：新增文档的 UTF-8、状态声明、本地链接、八组项目/团队/排期与入口链接单独检查；全目录 `node tooling/check-codex-plan.mjs` 仍受既有缺失文档、失效链接和其他文档缺状态声明影响，不能宣称全目录检查通过。工作区其他文件的空白检查问题不在本轮修订范围。

实施阶段以独立 Issue/PR 记录影响范围、验证方式和数据/权限风险。优先完成通用 rubric 作品链路，再做两个隔离样板，最后扩展到全部八个项目。
