# PBL Dynamic Interaction Gap Audit

> Audit date: 2026-10-19
> Scope: changes after `b161f6c`, current source tree, and the Codex proposal documents.
> Status: implementation gate; this file records what is real in the repository versus what remains proposal work.

## Findings First

### P0 - workspace contract validation is not reproducible on this UNC checkout

The source packages build independently:

```text
@qitu/contracts build   pass
@qitu/ai-client build   pass
@qitu/database build    pass
parent-companion typecheck pass
```

`@qitu/api typecheck` still resolves stale `node_modules/@qitu/contracts`, `@qitu/database`, and `@qitu/ai-client` snapshots on this UNC path. It reports missing exports that exist in the source packages (`TutorPhaseProjection`, `AnswerInteractiveQuizResponse`, `adminTeamVersions`, `projectPlanAdjustments`, and `@qitu/ai-client/quiz-bank`). A frozen validation command must either create real workspace links or use a clean local checkout; do not classify these errors as an optics business fix until resolution is corrected.

The failed `pnpm install --offline --frozen-lockfile` also shows that the UNC filesystem cannot reliably create the required Next.js symlink. It must not be used as an automatic repair step because it can overwrite the install snapshot and obscure user changes.

### P1 - optics block is still a guarded renderer prototype

`services/api/src/modules/ai-tutor/tutor-interactive-blocks.ts` emits `optics_experiment` from a title regex plus stage and `TheoryMastered`. It does not resolve a frozen template/team binding or experiment allow-list. `OpticsDiffractionScatteringCard.tsx` keeps parameters in local React state and sends one summary through generic tutor text. The contract lacks `specVersion`, `objectiveId`, stable `actionId`, idempotency, server range validation, observation events, and CER/rubric references.

Until that event protocol exists, the card must remain explicitly pilot/demo-only and cannot write mastery, artifact approval, plan revision, or growth records.

### P1 - adaptive micro-loop is documented but not wired

The repository has quiz attempts, hint levels, stall signals, and plan-adjustment owners, but the optics wave steps are static content. There is no server-owned `Observe -> Predict -> Manipulate -> Measure -> Explain -> Challenge -> Submit` action policy that classifies a response, selects the next bounded action, and records evidence against an objective.

### P1 - project/team freeze and outline persistence remain backlog items

The proposal names `templateVersionId`, `bindingId`, `teamVersionId`, and `bindingHash`, but the current optics injection path does not carry those values into the interactive block. `PlanOutlineStore` has a contract/design proposal but no verified PostgreSQL wiring in the current build. Formal project confirmation must freeze these references in one transaction before adaptive tutoring can depend on them.

The existing confirmation path calls `freezeProjectBinding`, but treats an `omitted` result as a warning and still commits the formal project. That is not fail-closed: a project can exist without a `project_binding_snapshots` row, after which Tutor has no governed team/version context. Make binding freeze mandatory (or explicitly create a governed free-project snapshot) before returning success.

### P1 - student visibility was broadened to piloting templates

`TutorWorkspaceService.searchTemplates` includes `published` and `piloting` versions. This is only safe behind an explicit pilot flag and active binding policy. Otherwise an unreviewed piloting template can enter student search results.

### P1 - Admin skill binding normalization

The skills page previously mixed runtime IDs and display names in full-array `enabledSkills` PATCH payloads. It now maps known legacy names to runtime IDs, drops unmappable values, blocks writes while the runtime catalog is unavailable, and serializes concurrent saves. Before production, change the unmappable-value path to fail closed (rather than silently removing bindings hidden by a partial catalog) and add component tests for normalization, catalog-empty/error states, partial failure, and two concurrent save attempts.

### P1 - Untracked local seed/probe scripts must not become production state

The working tree also contains untracked developer artifacts that were not modified:

- `database/seeds/optics-team-seed.sql` creates assistants, a team, members, and a team version, but does not create the governed template/binding/project snapshot or binding hash. Its `pbl_spec` is duplicated, one phase references `qitu-intake-assistant` without seeding that assistant, and the team/team-version leader values are inconsistent. Prefer the governed `services/api/src/scripts/optics-template-bootstrap.ts` path; treat this SQL as an isolated fixture until schema-level foreign-key, binding, and permission checks pass.
- `set_theory_mastered.sql`, `insert_mastery_events.sql`, and `query_events.sql` write or inspect mastery/gate state directly. They bypass the project confirmation and mastery owner paths and must never be used against shared, staging, or production data.
- `switch_to_deepseek.sql` changes all assistant model assignments and the tutor usage binding at once; it needs an environment-scoped, audited configuration path rather than a broad ad-hoc update.
- `test_model_runner.js` decrypts provider credentials and calls external model endpoints. It is machine-specific (`/root/...`), should not be committed, and must not print secrets or be run with learner payloads.
- `query_db.js` and `check_schema.sql` are machine-specific database utilities; keep them outside the application runtime or mark them clearly as local-only scripts.

These files are intentionally preserved for the user. Before merging, quarantine or move them into an ignored developer-tools area and replace state-changing probes with test fixtures that assert the same owner/permission/idempotency contracts as production.

### P1 - IMA is transport-ready but not binding-scoped

`services/api/src/modules/ai-tutor/ima-mcp.client.ts` already validates the endpoint, bounds responses, limits tools to the four read-only IMA tools, and re-checks tool authorization before each call. The new Theme-Session-Team-IMA proposal still needs to bind knowledge-base IDs and tool grants to the immutable project snapshot. `ImaSettingsService.canCall` currently checks server/agent/assistant/tool authorization, while the MCP call forwards model-supplied arguments; it does not enforce a binding-level knowledge-base allow-list. Add server-side argument validation/injection, citation evidence fields, and unavailable/permission-denied fallback tests before exposing IMA to the optics pilot.

The working tree now contains an untracked `packages/contracts/src/curriculum.ts` (exported by a user-modified `packages/contracts/src/index.ts`). Existing tracked schedule contracts live in `packages/contracts/src/pbl-learning.ts`, while generation logic lives in `packages/ai-client/src/curriculum.ts`. The draft v2 contract needs tests and API/template migration before it can be treated as canonical. The server bootstrap still publishes an 8-session/4-week optics version, while `OPTICS_16_SESSION_SPEC` describes 16 sessions; introduce a new template version and migration rather than changing the existing bootstrap key in place. Do not maintain two independently validated curriculum schemas or interpret 16 sessions as 16 new mastery objectives.

### P1 - the student project adapter is only a partial bridge

`apps/student-center/features/projects/data/api-projects-data-source.ts` now reads the learning plan and can submit quiz/evidence requests, but it still derives theory material by flattening objective descriptions, maps project task IDs to cached sessions, and leaves reflection submission unsupported. It must not be treated as the completed dynamic PBL client: task/session identity expiry, offline replay, answer-option versioning, and server-issued optics actions still need explicit contracts and tests. In particular, the adapter must not use a client-composed summary as experiment evidence or call the project advance command merely because a UI task was clicked.

### P1 - Admin model selectors now need provider/model pair semantics

Configured model IDs are not globally unique. The Copilot and profile-growth selectors must carry `providerId:modelId` (or an equivalent pair) and send both fields to the server; a provider-less `modelId` is ambiguous. The current workspace has stale package snapshots, so the Admin typecheck remains blocked by unrelated UI package exports; rerun after a clean workspace install and add a regression test for duplicate model IDs across providers.

## Non-canonical material

`docs/plan/codex` is the current proposal. `docs/plan/antigravity` and `docs/plan/combined` are historical comparison material; they must not define a second PBL state or storage model. Unsupported empirical effect numbers were removed from the Antigravity research note. Grok Search MCP returned `sources_count: 0` for the latest upstream searches, so those results remain leads and not learning-effect evidence.

The student web app was not listening on `127.0.0.1:3101` during this audit, so the website assessment is source-level (routes/components/contracts) rather than a live browser acceptance test. Run the student app with governed seed data before treating visual or SSE behavior as verified.
