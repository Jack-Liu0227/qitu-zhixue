# Teaching arrangement and six-dimension profile

Date: 2026-10-22. Scope: presentation within existing template and student profile
pages. Navigation, PBL ownership, frozen project semantics and authorization stay
unchanged. This is a focused feature change, not a platform rewrite.

## Grounding and decision

The template page currently mixes team publication, binding drafts, lesson routing,
generation, validation and activation. The useful member/model/skill information is
hidden behind nested details and JSON. The current profile shows qualitative text
but no six-dimension observation framework.

Two complete alternatives were compared:

- A: combine a server-owned six-dimension read model with existing owner evidence.
  A future assessed value requires an explicit frozen rubric mapping and a verified
  owner receipt. AI continues to explain, not create official assessment facts.
- B: add a versioned six-dimension AI result to the existing candidate contract and
  extend template compilation, scoring receipts and owner acceptance together.

The independent review preferred A on integrity, edit scope, interface size and
compatibility. B currently lacks a connected graded-assessment producer; the
existing boolean lesson review and publication counts cannot supply numeric axes.
No new assessment store or second mastery database is introduced.

The current delivery is the interactive observation framework and truthful evidence
states. It does not pretend that a full six-dimension grading workflow exists.
An asynchronous user question separately scopes any graded-rubric expansion.

## Teaching arrangement

```text
Teaching arrangement          Team/version + schedule + real lifecycle status
Select/publish team -> assign lessons -> inspect capabilities -> validate/activate
-------------------------------------------------------------------------
Actual phase and lesson routes        Selected role/member inspector
Member selection                      Frozen provider/model pair
Actual schedule, not fixed ranges      Published canonical skill pins
                                      Tool/MCP subsets and knowledge scope
-------------------------------------------------------------------------
Server validation/readback            Save draft / validate / activate
Advanced JSON and historical recovery remain secondary tools
```

The reference direction keeps Qitu's pale blue surfaces, navy headings and blue
actions. A flat routing board and one inspector replace nested explanations. Real
member avatars and readable lesson rows carry meaning; decorative metrics do not.
The generated visual reference is a prototype, not a source of runtime data.

Published member models and skill pins are immutable ceilings. Changing a model
or adding a skill requires the existing assistant/team publication workflow.
Knowledge scope uses exact authorized IMA IDs; empty means no authorization.
All writes retain existing owner APIs, stable idempotency keys and authoritative
readback. Invalid JSON and failed saves retain the draft. No optimistic success.

## Six-dimension profile

The shared framework identifies problem discovery, scientific inquiry, logical
modeling, practical creation, collaborative expression and reflection/transfer.
The UI renders an interactive SVG hexagon and selected-dimension details, plus
existing interests, summaries, evidence and device management.

- Missing evidence and unconfigured rubrics are null, never a default score.
- Source kinds, keyword matches and activity counts do not become abilities.
- Existing evidence can be shown as unassigned learning records, not silently
  attached to a dimension without a frozen mapping.
- A partial set of assessed axes must not imply a complete filled ability area.
- Reads do not generate models, write facts or recover permanently deleted data.
- Honest empty states explain the next action; pending work retains accepted data.

Keyboard access, reduced motion, the existing night theme, mobile width, request
identity and permission/error/offline states are part of the feature, not follow-up.
