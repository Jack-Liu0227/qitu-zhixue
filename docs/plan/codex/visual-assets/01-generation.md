# Image 2 素材生成计划

> 状态：planned · 方案稿；数量、分辨率、体积均为制作目标，不是已生成结果。总览见 [README](./README.md)，接入规则见 [02-integration](./02-integration.md)。

## 1. 模型与执行路径

将用户所说的 image2 按 `gpt-image-2` 制作目标规划。官方模型页确认其支持生成、编辑和图像输入：[GPT Image 2](https://developers.openai.com/api/docs/models/gpt-image-2)。

需要区分两个执行环境：

1. **当前 Codex 辅助制图**：优先使用已提供的内置 image generation 工具；每个独立素材/候选单独调用。该工具当前没有显式 model 参数，不能仅凭工具名宣称底层一定是 `gpt-image-2`。记录实际工具与可获取的模型元数据，未暴露的字段明确记为未提供。
2. **必须审计为指定模型的制作或未来后台在线生成**：通过显式支持 `gpt-image-2` 的服务端提供商执行。先核验模型目录、图像能力、账户可用性和一次试生成；记录提供商/模型组合与请求凭证之外的回执信息。当前对话可用的内置工具不等于项目服务端已具备该能力。

首期不建设在线生成产品功能；先完成素材生产、入库和选择复用。如果后续选择显式 CLI/API 制作路径，使用现有 imagegen 技能附带工具，不临时复制一套 SDK runner；密钥只从安全配置读取，不进入聊天、素材清单或仓库。

官方当前资料将 GPT Image 2 透明背景标为 preview，应先做真实 alpha 验证。透明输出选择 PNG/WebP，不能把棋盘格或白底当成透明；如实际提供商不支持，记录失败并保留原模型约束，不悄悄切模型。参考：[图像提示与参数](https://developers.openai.com/api/docs/guides/image-prompting)、[创建图像接口](https://developers.openai.com/api/reference/resources/images/methods/generate)。本地技能参考文档关于透明参数存在较旧描述，实际实施应核对所用工具与官方能力，不直接假定旧 CLI 已支持 preview。

## 2. 统一视觉规范

基准参考：`packages/ui/assets/assistant/qitu-companion.png` 与该目录 README。沿用启途现有蓝白简化立体风格，配色基于现有品牌：钴蓝 `#0038b2`、深蓝 `#132646`、青色 `#37cddd`、白色。

| 项目 | 制作约束 |
| --- | --- |
| 助手 | 同一蓝白陶瓷机器人家族，统一脸型/眼睛/材质/视角；用一个大轮廓符号区别款式 |
| 团队 | 简洁组合徽记或多个协作节点，视觉上能与单助手头像区分 |
| 模板图标 | 以主题对象为主体，如光学棱镜、轨道小车、编程游戏对象；避免都画成机器人 |
| 封面 | 与主题图标共享材质和颜色，但独立构图；不把小图标放大拉伸为封面 |
| 构图 | 图标居中，主体约占画布 72%–80%，保留裁切安全区；圆形与圆角方形均可用 |
| 小尺寸 | 优先 32 像素可辨轮廓；24 像素仍可识别为图形。角色说明继续由文字承担 |
| 文字 | 图片内不写名称、中文标题、模型名、版本号、公式和状态文字；由 UI 渲染 |
| 状态 | 不烘焙在线点、锁、已通过勾选、启用状态；由真实服务端状态独立覆盖 |
| 光学 | 使用主题性示意。实验条纹、测量数据、公式图与结论仍来自经验证的仿真/教学组件 |
| 背景 | 头像/图标优先透明；封面允许低对比背景。透明边缘不带白圈或暗色光晕 |
| 风格一致 | 同一批使用固定参考图和版本化风格提示词，逐个素材独立生成后拼评审页 |

以下 ID 是**拟议素材 ID**，不是助手 ID、技能 ID 或权限标签。使用该头像不会自动获得对应角色、工具或模型能力。

| 素材 ID | 选择器名称 | 主要视觉区分 | 可选使用场景 |
| --- | --- | --- | --- |
| `avatar-general-v1` | 通用搭档 | 基准蓝白机器人，清晰轨道徽记 | 全局默认候选，未单独选择的新助手 |
| `avatar-explorer-v1` | 探索发现 | 罗盘或单一透镜式探索符号 | 兴趣启发、意图澄清、项目入口 |
| `avatar-concept-v1` | 概念理解 | 简洁书页与一束启发光 | 概念教练、理论讲解 |
| `avatar-experiment-v1` | 实验探究 | 一个可辨识实验观察装置符号 | 物理仿真、实验设计 |
| `avatar-coding-v1` | 编程创造 | 蓝色积木模块/极简代码窗口轮廓 | 编程向导、作品构建 |
| `avatar-data-v1` | 数据分析 | 三条简洁数据柱或点线图 | 数据比较、学情分析 |
| `avatar-review-v1` | 表达评议 | 对话与证据卡片轮廓 | 评审、答辩、CER 表达 |
| `avatar-growth-v1` | 成长陪伴 | 小芽或向上延伸路径 | 反思、成长回顾、鼓励 |
| `avatar-coordinator-v1` | 协作组织 | 三个有序连接节点 | 总导师、平台管家、团队协调 |
| `avatar-creative-v1` | 创意设计 | 调色板或单一创意火花 | 创作、设计、跨学科探索 |

每款保持同一机器人身份体系，配饰不堆叠。既有 `qitu-companion.png` 作为兼容兜底继续保留，不额外计入这 10 款新素材预算。普通助手自动继承默认；只有需要个性化时才选择某一款。

现有助手可在一个批量面板统一设置，或全部继承默认。若需按业务角色分组推荐，必须由管理员明确确认对象清单，不根据标题、ID 前缀或头像名称推导运行时角色。

## 5. 批次与数量预算

| 批次 | 内容 | 生成量目标 | 留用量 |
| --- | --- | ---: | ---: |
| 样图 | 通用/概念/实验头像、光学团队图、光学模板图标、光学封面，各 2 候选 | 12 | 6 |
| 助手补齐 | 其余 7 款头像 | 7 | 7 |
| 主题补齐 | 动能/编程各团队图、图标、封面 | 6 | 6 |
| 首期合计 | 不含返工与失败请求 | 25 次单素材生成 | 19 |

初始另预留最多 4 次针对性返工作为预算参考；不代表必需消耗，也不保证所有上游失败均不计费。样图不达标先修订风格，再开始余量制作；不一次性生成全部候选后才评审。

费用计算使用实际提供商单价和真实 usage：候选生成 + 参考图输入 + 重试/编辑 + 存储/流量。先记录样图实测，再估计余量；本计划不虚构固定总价或固定每张耗时。尺寸转换不重新调用模型。若未来服务端批量生成，设置预算上限、有限重试与并发上限；请求超时但结果未知时先查回执，不盲目重复付费。

## 6. 文件与导出规范

| 用途 | 母版目标 | 运行时派生 | 初始体积目标 |
| --- | --- | --- | --- |
| 助手头像/团队/模板图标 | 1024×1024 PNG | 64、128、256 像素 WebP/PNG，按显示尺寸选用 | 64px ≤ 12KB；128px ≤ 24KB；256px ≤ 60KB |
| 模板封面 | 2048×1152 或工具支持的相同比例高分辨率母版 | 640×360、1280×720 WebP | 分别 ≤ 120KB、240KB |
| P2 空态 | 与现有槽位一致的母版比例 | 320/640 宽度 | 各页仅按需加载 |

上述为性能预算；视觉达标优先，超限须记录原因。当前内置工具无显式像素尺寸参数时，以真实输出尺寸为准，检查后派生目标尺寸，不伪报生成分辨率。只做确定性缩放/编码；内容修图与背景修改走 image generation 编辑流程。

- 制作母版与评审材料：拟放 `design-assets/visual-library/v1/`，保留选中原图、提示词和来源 manifest。是否将全部母版入 Git，按大小选择现有制品存储；需保留可恢复的引用和校验和。
- 运行时内置素材：拟放 `packages/ui/assets/library/`，用版本化文件名或内容摘要，静态导入后由各应用产物交付。
- 共享渲染索引：拟放 `packages/ui/src/visual-assets/`，只处理资产 ID 到打包资源的映射，不存对象授权或助手角色路由。
- 稿件默认目录不是产品存储；选中输出必须复制入工作区或受管理存储后再接线，不直接引用 Codex 私有生成目录。

每条来源 manifest 至少记录：`assetId`、用途、风格版本、提示词版本/正文、参考图摘要、工具、真实可得的模型标识、生成时间、原图与派生文件摘要、尺寸、透明度、审核结果。未提供的模型/usage 标为未知；禁止写入密钥、原始学生内容和签名 URL。
