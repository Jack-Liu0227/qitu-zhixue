## 4. 课件完整可见：正式录制的前置验收

### 4.1 问题定位与修复范围

- 区分页面裁切和录制源裁切：实际视口、浏览器缩放、录屏区域、播放器显示尺寸逐项对齐。
- 检查聊天区、课件区、底部输入框及弹层之间的高度分配；检查嵌套滚动容器、`overflow`、固定高度、Mermaid SVG 与公式宽度。
- 验证流式回复、滚动追踪、翻页、展开历史课件、打开评价抽屉后，当前课件是否被挤出视野或遮住。
- 优先在现有导航和页面架构内解决。确需改变冻结的 UI 信息架构时，先更新产品文档并走评审；不将临时浏览器 CSS 注入当成线上修复。
- 不以无限缩小字号、降低浏览器缩放到不可读，或只补一张全页长截图代替问题解决。

### 4.2 可见性标准

1. 录制采用固定 16:9 画面，优先试验 2560×1440、100% 浏览器缩放；设备无法原生支持时选择实际可用的 1920×1080，重新验收，不通过后期放大冒充高分辨率。
2. 当前教学页/步骤的标题、主体图示、公式、图例、说明和必要操作控件完整可读。完整可见以当前教学步骤为单位，不要求将整段长对话同时塞进一帧。
3. 一屏放不下的内容使用已有分页、演示或全屏入口；若功能不足则先修复。长代码/表格先交代整体，再逐段滚动展示，保留上下文与首尾，不快速掠过。
4. 每次翻页、动画、公式与图表渲染完成后再留镜；简单内容至少稳定 3–5 秒，复杂图表 6–10 秒，按实际阅读需要延长。这是拍摄节奏要求，不是学习效果指标。
5. 新消息、加载结束和评价结果不得把正在看的课件自动拉走；操作反馈不被输入框或浮层覆盖。
6. 全屏/退出全屏、下一个步骤、返回课件、模拟观察保存、错误恢复均可用，且画面没有未说明的横向截断。
7. 验收实际编码后的 MP4：检查每个课件页/步骤的稳定帧与转换前后片段；DOM 边界和浏览器截图仅作辅助证据。
8. 字幕位置也属于可见性验收：优先在成片画布中预留独立字幕区，完整录屏画面按比例适配其余区域，不裁掉课件边缘。试片中确认缩放后公式、代码与图注仍清楚；必要时提高实际录制分辨率或调整展示布局，不能用字幕覆盖教学内容。
9. 源录像保存无后期字幕的干净画面；最终成片显示字幕，剪映工程中字幕保持可编辑文字，便于用户修改或关闭。

发现不合格即暂停推进新的学习活动，保存失败片段及问题证据。修复后先补录可视化验收；若已发生不可逆学习写入且原画面缺失，补录必须标为回看，不得冒充原始连续过程；必要时重新从模板创建项目完成一遍合格录制。

## 10. 指定音色、解说文稿和字幕

### 10.1 音色基准与合成

- 用户指定样本：`\\192.168.137.2\科研资产\Study\qitu-zhixue\提交文件\视频\声音试听\3_云扬_磁性科技男声.mp3`。
- 样本 SHA-256：`13ac686b68edfa1bd22afcbc2c365b3312d333677c4d4fe04ea44a9d660bf5ed`。
- 以样本听感为准，不把这段约 9.67 秒的试听循环铺满视频。用对应声线生成与本轮内容匹配的完整旁白。
- 文件名“云扬”对应的首选候选是 `zh-CN-YunyangNeural`；微软官方目录列有这一普通话男声，见第 14 节。这里是候选映射，不声称已经证明样本的原始合成来源。先合成试片、对照音色与节奏并记录配置，不能静默换成其他声线。
- 先核查样本是否有可复用生成参数；无记录时以自然音高、接近样本的正常解说语速试配。语速、音高、停顿和发音表在试片验证后冻结，两项目保持一致。
- 按句/短段合成，每句绑定项目、课时、镜头和字幕 ID。保留可改文稿及配置；修改一段时只重生成相关音频并重新对齐后续时间。
- 输出编辑用 WAV（统一 48 kHz，重采样不等于增加原始音质）及必要的原始合成音频；最终 MP4 使用 AAC。旁白初始混音目标约 -16 LUFS、真峰值不高于 -1 dBTP，结合实际试听调整，避免失真和课间音量突变。

### 10.2 解说内容与真实过程的对应

- 为项目创建、各课目标、每页/步骤的关键教学内容、操作原因、预测/观察、实际反馈、修订及完成结果提供清楚解说；不机械朗读所有菜单或重复长段页面文字。
- 光学优先解释图样、参数及证据关系；雷霆战机解释本次代码改动、运行结果和测试依据。公式、单位、变量和专有词逐项校读，区分配音的自然读法和字幕中正确的符号。
- 旁白根据真实录像撰写，不能预告尚未发生的通过、捏造学生回答或评价。开头说明为流程录屏配解说，不把后期合成声音伪装成网站实际发出的语音。
- 全程保留关键操作、真实失败、等待和恢复。内容覆盖完整不等于每一秒连续说话；阅读、思考、运行和模型等待保留自然停顿。
- 录制时为课件留足阅读时间。后期发现解说放不下时，先精简文稿或在合理范围内微调语速；确需延长静态展示时使用独立、标为“讲解停留”的定格片段，事件索引同时记录原片时间与成片时间，不冒充实况等待。
- 原声和旁白独立保存。应用语音与解说冲突时避免双重播报；保留原声轨供用户恢复，旁白期间压低游戏等音效。默认不额外加入背景音乐。

### 10.3 字幕制作与遮挡控制

- 每句实际旁白对应中文字幕；其他保留的可辨识语音也要有经校对的字幕。非语音点击/游戏音效不强行转成文字。
- 按实际生成音频的时间戳对齐，缺少可靠时间戳时做音频对齐；不能仅按字数猜时间。逐课校对，初始验收目标为字幕起止与发声偏差不超过约 200 ms，并检查片头、中段和片尾没有累计漂移。
- 使用简体中文、自然断句，通常 1–2 行，不拆散数值与单位或关键术语；优先使用清晰无衬线字体、白字深色描边/适量底色，字号依据实际画布与试看可读性确定。
- 在预留字幕区展示，避免遮住公式、代码、实验参数、操作按钮和回执。每个复杂画面都检查实际导出帧，而非只检查字幕模板。
- 工程内为可编辑文字片段；逐课交付 `lesson.srt`，总片交付累计偏移后的总 SRT，编码 UTF-8；另保留 caption-map，方便文稿、音频、字幕同步更新。最终交付 MP4 自带可见字幕，不依赖播放器加载外置文件。

## 11. 两个可编辑剪映工程

### 11.1 必交付工程与轨道

分别创建 `光学干涉与衍射_全流程_20261025` 和 `雷霆战机_全流程_20261025` 两个正式工程。工程从各课原始素材组织时间线，不能只导入一个已经压平字幕和旁白的总 MP4 来充当可编辑工程。

| 轨道 | 内容 | 用户可修改内容 |
| --- | --- | --- |
| 主视频 | 项目创建、按课时排列的实际录屏与课间过渡 | 裁剪、调整时长、替换片段与顺序 |
| 截图/补充图示 | 与本轮内容对应的截图、必要的讲解停留 | 替换图片、调整展示时间和尺寸 |
| 章节标题 | 项目名称、课时编号和标题 | 文案、样式、位置、持续时间 |
| 字幕文字 | 与实际语音逐句对齐的字幕片段 | 文字、断句、样式、位置、时间 |
| 旁白音频 | 指定云扬声线的分句或短段音频 | 音量、静音、移动、替换；改文稿后可重新生成 |
| 原声/游戏音效 | 实际录制的系统声音，存在时保留 | 音量、静音及与旁白的混音关系 |

各课在时间线中形成连续、清楚命名的片段区间；优先使用本机版本支持的标记/分组，并始终提供独立章节表定位。工程展示布局固定，保留课件完整画面和字幕区。音频是可替换音频素材，不将“修改字幕”误称为能自动改变已生成的语音。

### 11.2 工程创建与兼容性验证

1. 先在临时试片草稿验证本机剪映 11.6 的新建、素材导入、文字轨、音频轨、保存重开与导出；不修改用户现有工程。
2. 可评估已安装的草稿工具以提高批量组织效率，但必须通过本机版本实际打开测试；本地 JSON 存在或脚本返回成功不算工程交付。
3. 若草稿生成工具不兼容，改用剪映界面新建、导入和分轨编辑；不私自降级剪映或改写用户已有草稿。
4. 两个正式工程分别打开，检查各课的开场、中段、结尾、字幕及音频；在备份副本中实际修改一条字幕、调整一段旁白、替换一张截图，保存重开，确认修改确实保留。正式交付版本恢复为正确内容。
5. 在本机项目列表中保留两个可继续编辑的工程，并记录版本、工程 ID 和本机绝对路径；关闭或确认写入完成后保存完整工程备份。
6. 工程依赖素材固定存放并提供路径清单与校验值；项目可引用根目录中的逐课素材，不无谓复制大量视频。交付包含工程及其全部依赖，不只交草稿 JSON。重定位验证在副本中进行，提供本机路径与共享包路径的对应说明，避免打开时素材丢失。

## 12. 录制、切分与导出

- 执行修订（2026-10-25）：桌面试录受到其他窗口切换影响，已判定失败并清除含无关画面的临时视频。正式网站流程改用独立可见 Playwright 浏览器上下文的原生录像，固定视口 2560×1440，不依赖桌面焦点。代码与游戏实机运行另以目标应用/实际渲染帧及运行日志采集，作为对应课时的独立真实实践片段；合成时保留操作顺序、时间和来源标识，不把单独采集冒称为全桌面连续录制。剪映编辑前核对工程名，避免与其他正在使用的工程混淆。
- 全过程主录制从灵感空间开始，在课时边界打时间标记而不停止主录制，避免丢失上一课完成到下一课自动开场的过渡。
- 如需分段录制，先停止学习操作，保存录制中断原因和恢复点，确认新的录制已开始后再继续。故障和必要重试保留，不伪装成连续一次通过。
- 最终 MP4 统一选择 H.264、`yuv420p`、固定 30 fps、统一实际分辨率和 AAC 48 kHz 音轨；每个总片及逐课成片都有经校对的云扬旁白和可见中文字幕，原声按第 10 节混音。
- 原始连续录像完整留存。每课 `lesson_clean.mp4` 和剪映主视频轨取自同一批原始录像；`lesson_full.mp4` 和两个总片包含完整过程及后期配音字幕。总片包含创建、全部课时、项目结束和恢复过程，不删掉失败与等待来冒充全程。
- 检查切分起点、终点和拼接处，避免关键帧切分导致漏帧、丢开场或声画漂移。课间过渡分配到确定章节，并在索引中标明。
- `chapters.csv` 记录各课在总视频中的起止时间；`shot-index.csv` 记录镜头主题、对应原始片段、片段内/总视频时间、截图路径和简短剪辑说明。
- `import-order.csv` 提供项目、课时、序号、相对路径、素材类型和时长，是工程依赖与导入顺序的辅助索引，不能替代第 11 节要求的两个真实剪映工程。
- 从已验收的工程导出总片与逐课成片；逐课导出的字幕时间重新从零开始。检查总 SRT 的课时累计偏移、全部语音结束位置和最后一帧，防止导出范围截掉尾音或完成回执。
- 可另做精简展示版，但它不能替代本次要求的完整视频；未经需要不主动生成更多成片造成混淆。

## 13. 问题处理、隐私与验收

课件裁切、教学关键画面不可读、录制失效、项目串线、门禁异常和无法保存证据均停止后续推进，登记课时、活动、视频时间、截图、预期/实际结果与恢复情况。网络/模型故障保留已保存证据后走正常重试，不重复创建项目或伪造完成。

截图和日志只记录本轮授权演示内容。认证信息、Cookie、令牌、个人资料和无关学生数据不得进入素材包。网络证据采用必要字段的白名单摘要，不默认导出含敏感头和完整正文的 HAR。最终包不保存登录态。

正式验收分五项，分别记录通过或未通过：

1. **功能完整**：两个新 projectId，模板与绑定匹配；所有实际课时完成且有服务端回执；作品、评价和归档能只读回查；没有绕过门禁或手工写入学习事实。
2. **展示完整**：每页/步骤有实际视频与对应稳定截图；关键课件、公式、图表和操作反馈完整可读；本地游戏真实过程已录到；用户指出的裁切问题通过实际视频验证。
3. **配音字幕完整**：指定样本与实际声线、参数已有记录；每课重要教学与操作环节有对应解说；字幕文字准确、同步且不遮挡课件；原声不与旁白争抢；无削波、明显音量跳变或错误读音；逐句音频、文稿及 SRT 可独立修改。
4. **工程可编辑**：两个正式工程在本机剪映内打开、保存与重开成功；字幕、旁白、原声、视频和图片独立可改；完成真实修改验证；工程备份及全部素材依赖齐全，不以单条压平视频替代工程。
5. **媒体完整**：两个总 MP4 和逐课 MP4 均可播放且可完整解码，有实际可听旁白和可见字幕；时长与章节表、原始片段及有记录的讲解停留对应；逐课检查开场、所有教学步骤、保存、完成和拼接处；无漏课、黑屏、未说明定格、截断尾音或累计音画漂移。

每完成一课立即整理与验收原始录制和学习证据，再继续下一课；后期依次完成逐课配音、字幕与工程验收。最终报告列明文件路径、项目 ID、实际课时数、各视频时长、截图数量、音色配置、字幕文件、两个剪映工程路径及版本、遗留问题，以及新项目/新学生基线和代理辅助操作的真实验证范围。计划阶段不会将待执行项标为完成。
