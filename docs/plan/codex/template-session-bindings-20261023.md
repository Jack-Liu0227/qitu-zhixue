# 课时级助手与团队绑定

关联 [需求与验收条件](../../issues/20261023-template-session-bindings.md)。2026-10-23 已完成生产部署与绑定流程验收，见[上线记录](../../admin/release-session-bindings-20261023.md)。绑定验收不等于完整学生课程或真实模型教学效果验收。

## 使用方式

在现有 Admin 项目模板编辑页选择默认团队，再逐课选择已有团队及其助手，或“团队 · 负责人主讲”。可先把默认团队应用到全部课时，再分别调整，点击“保存教学安排”、检查配置、校验并启用。模板页不展示团队版本选择，也不要求手动发布团队。团队模式继续使用课程明确声明的协作助手与触发条件，不会自动让所有成员发言。

团队页维护团队与助手，模板库只选择和使用。修改已生效或已校验的教学安排后保存，服务端自动建立新草稿并保留原资料范围；旧项目保持原快照。没有课时排期的旧模板明确提示先创建课时合同，不凭标题猜测 8 或 16 课时。缺能力、协作成员、模型或知识库授权仍会阻止启用。

## 合同与服务端边界

`POST .../bindings/prepare-current` 接受真实 teamId、assistantId、逐课选择和团队 updatedAt，不接收客户端团队快照。Admin 保存时复用团队 owner 自动记录不可变配置，再保存教学安排；保留内部快照是为了历史项目与权限边界，不是新增用户操作。外层与各子步骤使用稳定幂等键，中断后重试复用相同快照和绑定。源教学安排修改或团队修订不一致会拒绝保存。

团队不必重复定义课程工作流：自动教学快照允许没有独立 PBL 工作流的启用团队，课程与实践门禁仍由既有模板及服务端 owner 管理；显式关闭理论门禁或允许自主推进的团队配置仍拒绝。模板编辑器通过 `GET .../bindings/:bindingId/team-snapshots` 读取当前安排实际引用的快照，不再依赖全部团队历史版本列表。损坏的旧快照单独报告，不返回未经验证的成员，也不阻止重新选择已有团队建立新安排。

保存新安排保留原知识库、MCP 范围；更换团队 slot 时，沿用的知识工具还必须存在于新助手的冻结授权中，不因新助手拥有更多权限扩大原范围。未启用的 draft / validated 安排可以通过原 retire owner 撤销，带幂等与审计，保持现有 active 绑定不变。

`TeachingBundleDraft.sessionAssignments` 是可选、显式、逐课的 Admin 选择。每项包含正整数 sessionIndex、不可变 teamVersionId，以及 team 模式或 assistant 模式的稳定 memberId。省略该字段的旧绑定继续使用旧的模板团队/导师一致性校验。

服务端按实际冻结 profile 验证全部课时，再解析每个被选团队的发布快照。每个团队只编译分配给它的课时，继续校验本课要求的技能、工具、协作成员、模型 pair 和 IMA 权限。根教学包保留原 binding teamVersionId，增加各课的选择及其他团队的编译包；所有内容共同进入原 bundleDigest 与 bindingHash。现有 JSONB 保存机制即可承载，不新增状态库或数据库迁移。编译仍受原有 2 MiB 合同上限约束。

Tutor 从 owner 保存的课时完成记录选择当前课时，再选取对应团队包。实验授权复用相同选择；协作 scope 保持根绑定身份，worker 在读取当前学习课时后选择其冻结团队，继续校验对象与证据。模板中的 TheoryMastered、实践活动、作品审批、审计和完成规则继续由原 owner 管理。

编排界面按课时顺序展示。四阶段仍是既有项目治理与安全门禁的兼容表示，课程不再因此被限制为四组教学者。此次没有删除旧项目状态枚举或绕过实践门禁。

## 权限、错误与日志

复用原 template binding 对象权限、幂等键、乐观并发校验和 create/draft/validate/activate 审计。新逐课路由的保存、校验和启用仅限 Admin，越权返回 `BUNDLE_SESSION_ASSIGNMENT_FORBIDDEN`。新增 `BUNDLE_SESSION_ASSIGNMENT_INVALID` 拒绝非法输入；编译错误包含 `SESSION_ROUTE_INCOMPLETE`、`TEAM_VERSION_UNAVAILABLE` 和 `SESSION_ASSIGNMENT_ROUTE_MISMATCH`，运行时缺冻结路由返回 `PROJECT_TEACHING_ROUTE_INVALID`。目录、断网、权限和回读失败在页面明确显示；不会乐观显示启用成功。
