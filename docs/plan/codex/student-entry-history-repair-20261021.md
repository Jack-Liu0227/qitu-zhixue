# 学生探索入口、项目历史与教学绑定修复

> 状态：已部署到 study-remote，8 个启途服务已重启并完成线上冒烟。发布与最终验证见 [发布记录](../../admin/release-study-remote-pbl-20261021.md)；下文生产只读核查描述部署前基线。未自动激活教学绑定或恢复旧项目。

## 截图问题与实际原因

1. Admin 的“教学角色与知识范围配置”是课程版本的教学合同编辑区，包含角色、课时路由、模型供应商与模型、技能版本、知识库范围。旧页面在没有可编辑草稿时仍展示空白 JSON 框，难以理解。历史团队版本不能直接作为新教学合同；必须发布包含助手快照的团队版本。
2. 生产只读汇总发现：截图对应一个账号，共 18 个项目，均处于进行中，15 个有探索来源；创建时间覆盖 2026-09-27 至 2026-10-20。全库没有重复的非空 `source_exploration_id`。这说明截图显示的是多个已持久化项目，不能仅凭标题相似判定重复写入，也不能认定所有记录都来自学生本人手动确认。没有读取或输出原始对话，没有按名称删除或合并项目。
3. 旧项目缺少完整冻结教学绑定时，服务端拒绝继续教学是现有权限规则。学生端不能自动换用当前 active 团队。旧界面缺少只读查看和恢复说明。
4. 自由探索链接没有 `new=1`，会触发默认继续当前项目。推荐模板虽然创建了带模板版本的 exploration，但对话显示与模型执行仍直接使用全局接待助手，且没有探索开场白。

生产 Student 构建仍为旧版，未包含上一轮的分页、项目显示偏好功能；生产不存在 `student_project_lists` 表。源码、生产构建和数据库迁移是三个不同事实层。

## 使用方法

Admin 在课程版本的“导师团队配置”中依次操作：

1. 选择团队，点击“生成当前团队版本”，发布当前助手配置的不可变快照。
2. 点击“保存团队绑定”，选择该课程版本支持的课时安排，核对每个阶段的导师。模板指定的助手必须属于该团队；不匹配时按页面提示调整团队或审核新课程版本。
3. 点击“生成教学配置”，核对角色、模型、技能与知识库摘要。默认不授予知识库权限；需要资料时，通过 Admin 已授权目录配置具体知识库引用，再由服务端校验。高级 JSON 编辑保留在折叠区。
4. 点击“校验并启用绑定”。只有服务器回读确认后才显示已生效。
5. 如需恢复截图中的历史项目，在“历史项目会话恢复”填写具体原因，逐个点击“确认恢复此项目”，再回学生端重试。已有有效冻结配置不被替换；不改变理论掌握度、阶段、作品通过状态。

学生从灵感空间点击模板对话入口，先进入模板探索。配置就绪时由该模板明确绑定的已发布团队负责人接管，使用同一角色固定的提示词、模型供应商与模型；配置尚未就绪时明确提示，并仅由接待助手整理问题。学生确认前不创建正式项目，也不授予项目知识库或实践权限。自由探索入口显式创建探索会话，自动展示开场和三个可点击的起步方向，刷新继续同一个探索。

## 实现边界

- 复用现有 exploration、binding、Tutor session、项目列表 owner，不新建教学状态机。
- `TutorProjectContext.exploration` 只投影真实探索及模板信息；团队解析使用模板版本、active binding 和不可变团队版本，拒绝按标题猜团队。
- 正式项目继续使用原冻结合同；探索仅预览当前公开模板配置，正式确认时仍须在原事务冻结并再次校验。
- 开场由服务端生成并持久化一次，不调用模型、不产生掌握度或作品事实；并发写入冲突回读实际已保存首轮。
- 项目历史只读接口同时校验项目和会话归属；不创建会话，不执行教学工具。学生端禁用历史记录中的答题、实验与提交动作。
- 列表每页 12 条，桌面最多三列，手机一列；分页属于主列表，下一步属于侧栏。保留创建日期、当前选择和收纳操作；收纳仅改变显示偏好。
- 不以这些源码与隔离测试宣称真实模型、IMA 教材检索或完整师生课堂链路已验收。
