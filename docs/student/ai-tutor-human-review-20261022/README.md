# AI 搭档按课时教学：人工审查稿

日期：2026-10-22。状态：**待人工审查，未批准实施**。

本轮只核查源码、读取线上配置、验证已部署的纯文本校验函数，并编写方案。没有修改业务代码、教学配置、学生项目或部署服务。本稿提出的界面、合同和教学策略变更均待审。

## 需求理解

需要审查的是学生端 `/student/tutor` 内部的完整学习体验：模板进入、固定开场、确认立项、逐课教学、动态课件、讲解与练习、导师协同、证据评价和进度恢复。学生应当始终知道“第几课、正在做什么、为什么这样教、还缺什么证据、下一步是什么”。

“项目进度与课时一致”落实为：以冻结课表及实际完成回执展示进度；当前课时、主讲导师、活动、课件和完成条件来自同一个范围。学生端不再展示固定四阶段主树；学习阶段由本模板的课时和教师定义的教学单元表达。四个宏观 PBL 阶段保留为内部治理及门禁背景。正常知识讲解允许给出定义、公式、示例和结论；待答题、正式考核与学生独立产物另有保护规则。

## 已确认的问题

| 优先级 | 事实或发现 | 对学习的影响 |
|---|---|---|
| P0 | 当前线上 16 课时均未包含 `completionSpec`；远端课时完成 owner 明确拒绝缺规则的完成请求 | 动态板书可用，仍无法据此完成课时、解锁下一课；这是课程合同缺口 |
| P0 | 全局提示词禁止完整答案和最终结论，文本校验按措辞、长度和问句收尾处理全部回复 | 正常讲解被拦截，不能将这种统一限制继续作为教学策略 |
| P0 | 第 1–2 课路由到启途助手，其冻结职责却规定确认后只交接、不代替团队教学 | 主讲职责与正式课程安排冲突；只加动态课件 Skill 没有解决职责匹配 |
| P0 | 当前绑定的 `knowledgeBaseIds`、`mcpServerIds` 均为空 | 具备板书工具不等于具备教材检索及有来源出题的条件 |
| P1 | 右栏先显示宏观阶段树，随后显示课时；正式项目开场仍生成“项目阶段图” | 学生看到两种进度语言，四阶段继续主导认知 |
| P1 | 已发布课时未声明 `requiredSkillIds`、`teachingRequirements`；编译器仍限制课时主讲与宏观阶段指定助手一致 | 课程需要的能力没有成为发布约束，同阶段难以安排不同主讲 |
| P1 | 当前模型得到整课活动清单，缺少统一的当前教学活动位置；板书“下一步”只翻图 | 生成可贴合本课，但尚不能保证按本课每一步执行和恢复 |

以上线上配置结论仅针对本次核查的光学模板，不推断其他模板相同。前端和服务端源码发现、线上已启用配置、上次真实请求结果分别记录在[现状核查](01-current-implementation.md)中。

此前通过的授权、板书和后台规划测试，证明了相应调用链可用，没有证明完整课时合同已经发布。这里将此前宽泛的“运行链路通过”收窄为实际验收范围。

## 建议的整体方案

1. 在既有模板合同中补齐每课固定开场、活动、主讲及协作角色、能力要求、完成规则和评价来源，发布新版本。
2. 右侧“项目进度”以实际课表为主，展示当前课与活动、已完成课数、证据缺口；宏观分组和门禁折叠查看。
3. 服务端按当前任务选择“讲解、示例、引导、练习、反馈、补救、实践、反思”，只在具体受保护任务中限制答案披露。
4. 每轮仅激活适用于当前活动的已授权 Skill；明确区分课堂执行、后台规划和画像成长任务。
5. 模型生成有界教学候选，现有 owner 校验并接收，学生回答或操作后产生回执，再决定继续本活动或进入下一课。

## 需要人工决定的事项

| 编号 | 待审决定 | 建议 |
|---|---|---|
| D1 | 学生主进度如何显示 | 主展示真实课时及课内活动，教学单元依模板；四阶段只在治理及门禁详情中查看，保留现有两个侧栏 Tab |
| D2 | 什么情况可以直接讲答案 | 概念讲解、教学示例可以完整说明；待答题和考核按题目 owner 的披露策略；反馈在提交后放行 |
| D3 | 立项前准备是否算正式课时 | 正式课程保持 16 课；立项前介绍和意图确认不计正式课时；正式第 2 课调整为问题与假设设计，移除重复立项检查点 |
| D4 | 谁主讲、如何协作 | 启途助手负责立项前；正式课按逐课矩阵选择主讲，必要协作显式配置，不能由四阶段包办分工 |
| D5 | 什么叫可发布、什么算一课完成 | 每课完成合同、必要 Skill/工具/资料范围和评价规则齐备才可发布为可教学；完成必须有 owner 回执 |
| D6 | 动态课件如何按步骤执行 | 复用计划/答题/证据 owner，补当前活动位置与恢复机制；翻页、生成和聊天轮数不产生完成事实 |
| D7 | 新策略如何处理历史项目 | 新合同单独发布；先评审技能历史包读取和项目迁移能力，明确哪些项目迁移、保留何种证据，不直接换旧 hash |

D3 是课程内容语义变更，需要课程设计者审查。若原设计确实要求“立项前 2 课 + 立项后 14 课”，必须另行确定探索证据的承接合同和计数规则，不能仅改页面数字。
