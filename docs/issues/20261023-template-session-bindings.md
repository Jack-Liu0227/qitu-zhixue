# 模板绑定与逐课教学者配置

需求：修复 Admin 部分项目模板不能更换团队；每课可选助手或团队；教学编排不再强制按四阶段分组。

源码诊断：旧编译器同时校验模板 `teamId`、阶段 `assignedAssistantId` 或课时 `leadAssistantId`。编辑器允许改选成员，却可能被这些固定引用拒绝。已校验绑定不能编辑，而重新编排入口只覆盖 active；新建绑定也没有复制原资料授权。没有 curriculum profile 的历史模板不能生成逐课教学包。

本次范围：沿用 template binding、TeachingBundle、学习计划和 mastery owner，新增显式的 `sessionAssignments`。不新建课程、项目状态、掌握度或绑定数据库，不改变产品导航。

验收条件：

- 同一课程中两课可以直接使用不同已有团队；也可以指定该团队内的单个助手。模板页不要求手动发布或选择团队版本，保存时由服务端自动记录配置。
- 保存、独立回读、校验、启用均成功后才显示生效。自动快照无法验证、非成员、缺课、重复或非法课号不得启用。旧快照异常明确提示，但不能阻止管理员重新选择现有团队建立新安排。
- 切换课时以服务端当前 learning session 为准，不能使用阶段号、标题或客户端 teamId；教学、仿真权限和协作任务使用该课冻结配置。
- 旧绑定不自动增加新语义；新绑定的课程、全部团队和教学能力都进入摘要。重新编排复制原配置并产生新绑定，原项目快照不变。
- 四个治理阶段继续兼容现有项目状态与门禁；它们不再控制新绑定的教学者分配，也不作为编排页面的四个固定分组。彻底删除历史状态枚举属于后续单独迁移，不在本次悄悄替换。

验证及使用边界见 [实施记录](../plan/codex/template-session-bindings-20261023.md)。
