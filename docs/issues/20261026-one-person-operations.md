# 一人运营与商业交付

用户授权：按一人公司方案推进四阶段实施及前端设计。

## 四阶段与验收

1. 商品准备：Admin 配置经营资料、服务条款、退款规则和绑定确切已发布模板版本的项目包。无价格、条款、课程或商户配置时不得开放购买。
2. 交易交付：家长为已授权孩子下单，服务端冻结商品及条款。微信支付 Native 下单、签名验证、支付查询和退款对账均在服务端。支付结果仅开通商业权益，正式项目仍需学生确认；两条正式项目确认路径检查权益，不改理论和作品门禁。
3. 试运营：经营页读取真实订单、咨询线索、课程交付和实际模型调用；空数据保持空态。真实付费家庭、教学质量和复购必须由实际运营验证，源码测试不代替验收。
4. 运营自动化：持久化待办与定时检查，显示退款、待跟进线索和交付异常；真实依赖探针和检查时间取代静态健康卡片。

## 前端设计与范围

保持官网、家长三项导航与 Admin 主导航。官网项目展厅加入项目包，家长首页加入课程订单区域，现有 Admin 运维页加入经营工作区。使用现有蓝色品牌、白色工作面、深蓝标题和青绿色证据状态。四阶段进度条表达真实依赖，金额用等宽数字，订单与待办采用可扫描列表，手机改为单列。覆盖 loading、empty、error、offline、permission-denied 与写入回读失败。

不虚构价格、商户、经营资质、付费用户或教学效果。经营资料由管理员提供，资料齐全不等于法律审核通过。商户私钥、APIv3 密钥和验签公钥仅由服务器环境/受限文件提供，前端只能看到是否配置。发布配置需回读，订单/回调/退款具备数据库幂等和审计。

## 实施限制与外部验收

本次完成仓库内工程实现及隔离测试，不直接执行生产迁移或真实扣退款。真实商户联调、实际用户试运营、主体/备案/业务资质及法律审核、生产 HTTPS/备份恢复演练属于外部验收项，必须保留未验证状态。
