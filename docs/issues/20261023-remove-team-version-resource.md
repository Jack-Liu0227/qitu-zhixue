# 移除独立历史团队版本资源与管家恢复

状态：已于 2026-10-24 00:08（Asia/Shanghai）上线；上线后浏览器验收通过。[可复核结果](20261023-remove-team-version-results.json)

用户明确要求修复 Admin 管家及其他助手不可用，并移除已弃用的历史团队版本，包括迁移历史项目所需配置、删除旧数据。

故障有两层：管家每轮读取全局旧团队版本目录，一条无关异常记录就阻断所有助手；模型仅返回 reply 时，解析器又把缺省 actions 误报为超过 24 步。现已删除旧目录依赖，缺省 actions 视为只读回答；非法动作、非数组动作、超过 24 步和越权写入继续拒绝。

实现与数据迁移：

- 删除独立团队版本 controller/service、发布/查询/运行时投影接口及前端 API；管家移除 `team.version`，用 `binding.prepare` 代替旧创建入口，能力合同为 1.4.0、50 项操作。
- 现有教学绑定 owner 直接捕获当前团队及成员配置，保存到 `pbl_template_team_bindings.team_snapshots`。不建立新的全局版本库，不再编号或手工发布团队版本。
- 课程、导师、项目恢复、成长投影和资源删除保护统一按绑定读取；跨绑定不能借用配置。当前撤权、理论门禁、并发修订、幂等性及对象权限继续校验。
- 0050 迁移校验主团队、课时团队及历史项目引用，迁入对应绑定后删除 `admin_team_versions` 和相关外键。正式库原有 16 条旧记录、17 个绑定、8 个项目快照；迁移后项目引用缺失为 0，绑定和项目冻结内容指纹均保持一致。
- 历史 v1 合同中的 `teamVersionId`、`teamVersionPublication` 等字段作为绑定内部标识保留摘要兼容，不再代表独立可发布或查询的历史团队版本。迁移记录、审计和受限备份保留以便追溯。
- 发布候选按服务器当前源码合并；数据库及原构建备份在服务器 `.codex-tasks/20261023-remove-team-versions/production-backup-v2`，目录 0700、数据库备份 0600。首次切换发现打包误排除 `cache` 代码目录，自动回滚成功；修正完整打包后再次迁移、启动成功。Drizzle 迁移日志已登记。
