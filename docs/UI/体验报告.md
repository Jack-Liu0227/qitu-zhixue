# 启途智学前端体验报告

审查日期：2026-10-21。对象为 [线上站点](http://122.51.130.204/)，使用页面提供的四角色演示账号。证据和范围见 [归档总览](README.md)。

## 1. 总体判断

产品已经建立了可识别的蓝白品牌、机器人形象和圆角卡片体系，四端主导航清楚，学生学习、教师关注、家长陪伴与 Admin 配置的职责也能辨认。当前最值得投入的不是重新设计导航，而是**修正展示事实、简化学习工作区、补齐窄屏操作和统一反馈语义**。

官网的完成度较高，客户端更像不同阶段的功能界面集合：相同标题出现多次，按钮、图标、状态词和留白密度不一致；演示标识、已接入能力与真实数据之间仍有让用户误解的地方。没有进行用户实验或转化率测量，因此不提供虚构的体验总分、提升比例或学习效果数字。

| 区域 | 可保留的优点 | 当前主要阻力 | 建议优先级 |
|---|---|---|---|
| 官网 | 品牌清楚，项目叙事有实物示意，合成内容有标识 | CTA 重复、体验入口预期不一致、手机首屏到项目示意的距离较长 | P1/P2 |
| 登录 | 四角色明确，字段标签完整，离线能禁用 | 演示入口与正式登录混排；恢复路径分裂；离线文案误导 | P0 条件项 / P1 |
| 学生 | 灵感、Tutor、项目、成长的导航完整；实践门禁可见 | 多面板挤压、内部术语、项目/画像展示事实不一致、工作台错误 | P1 |
| 班主任 | 关注学生可直接进入处理上下文，主导航克制 | 指标口径冲突、侧栏详情过密、手机表格不易读 | P1 |
| 家长 | 有具体陪伴建议、成长摘要和下一步，三项导航清楚 | 孩子选择区与项目统计矛盾；移动端仍用桌面提示 | P1/P2 |
| Admin | 配置集中，设置目录覆盖广，存在锁定和状态标识 | 双侧栏与宽矩阵、管家控制区拥挤、中英文和保存语义不统一 | P1/P2 |

P0：正式对真实用户开放前应先处理的条件性阻断。P1：影响可信度、任务完成或关键入口。P2：视觉、效率与一致性改进。这里没有把“所有溢出元素”机械判为缺陷，表格和标签条的局部横向滚动需要结合可发现性判断。

## 2. 登录与跨端访问

### L01 · 演示入口直接覆盖管理员角色（条件性 P0）

公开登录页提供四个“测试账号”按钮，本次通过其中的管理员按钮实际进入了管理端。页面说明这些账号用于共享演示联调，因此不能直接认定这是生产权限漏洞；但若该地址承载真实学生或真实配置，正式登录和可写演示管理能力必须先隔离。

建议：公开演示使用独立数据环境或受限演示身份；正式入口不展示演示凭证填充按钮。视觉上将“机构账号登录”和“演示体验”明确区分。不能仅隐藏按钮代替服务端权限约束。

证据：[登录桌面](01-login/login-desktop.png)、[管理端概览](05-admin/overview-desktop.png)。本次未测试管理配置写入，也没有把页面上的“Full Access”标签当作后台授权事实。

### L02 · 体验承诺和登录方式不匹配（P1）

官网同时出现“体验 AI 探索”“登录 / 免费体验”“立即开启 AI 探索之旅”，主要指向同一登录流程。登录页则说明账号由学校或机构发放，没有自助注册。首次访问者无法在点击前判断能否直接试用。

建议：对同一目的保留一个主 CTA；文案与实际流程对齐。若仅提供账号登录，可用“进入学习空间”，把“了解演示/联系体验”作为已有合作联系页的次入口。保持现有路由和导航顺序。

证据：[官网首屏](00-home/home-desktop-section-1.png)、[登录手机](01-login/login-mobile.png)。

### L03 · 四端未登录恢复不一致（P1）

在新建、无 cookie 的浏览器上下文中，四个入口均观察到 `auth/me` 返回 401；学生和教师最终回到官网 `/`，家长到 `/parent/login`，Admin 到 `/admin/login`。这证明本次访问没有得到登录态数据，不证明所有对象权限都已完整验收。

建议：统一前往 `/login?next=...`，保留合法站内目的地，并提示登录后返回哪个空间。避免会话过期时让正在工作的用户重新从官网找入口。

证据：[学生未登录](01-login/student-unauth-desktop.png)、[教师未登录](01-login/teacher-unauth-desktop.png)、[家长提示](01-login/parent-unauth-desktop.png)、[Admin 提示](01-login/admin-unauth-desktop.png)；结构记录见 [browser-metrics.json](06-evidence/browser-metrics.json)。

### L04 · 离线能阻止登录，但反馈语义不准确（P1）

模拟断网后提交按钮变为禁用的“离线，无法登录”，这是正确反馈。上方通用横幅却写“部分操作已暂存在本机。网络恢复后将自动同步”，会让用户误以为登录或凭证可以排队提交。手机上“班主任账号”“管理员账号”按钮也出现不自然断行。

建议：登录专用提示改为“当前网络不可用，请恢复网络后重新登录”，不承诺缓存/自动同步。演示角色按钮改为两列或更合适的换行规则。

证据：[离线手机](01-login/offline-mobile.png)、[空表单校验](01-login/empty-validation-desktop.png)。

## 3. 官网与主页

### H01 · 首屏动作和信息密度需要收敛（P2）

顶部与主视觉有多个同向 CTA，统计卡片、能力标签、三类项目标签和九个分镜按钮同时争夺注意力。桌面主标题还出现“长 / 成”的跨行拆分，弱化了原本清晰的句意。

建议：保留主 CTA 和一个解释型次 CTA；标题按语义换行；项目示意控制保留暂停、项目切换和当前步骤即可，九个分镜可折叠。手机上将统计从三张高卡片压缩为一行简要信息，让具体项目更早出现。

证据：[桌面首屏](00-home/home-desktop-section-1.png)、[手机首屏](00-home/home-mobile-section-1.png)、[手机后续屏](00-home/home-mobile-section-2.png)。本次测得手机文档高度约 5463 CSS px，属于单次渲染尺寸，不是性能指标。

### H02 · 小规模真实数据不宜承担主要说服任务（P2）

主页如实展示 4 名学习者、1 所学校、1 个公开模板，没有夸大规模。但这些数字在首屏占比较高，无法充分说明“孩子能做什么”。项目展厅更适合用已公开、已审核的模板和具体产物说明价值。

建议：保留真实统计，降低视觉权重；把当前公开光学模板的任务、预期作品和学习过程放到更显眼的位置。未公开的学生作品不得为了填满页面而取用。

证据：[官网主页](00-home/home-desktop-section-1.png)、[项目展厅](00-home/showcase-desktop-section-1.png)。

### H03 · 动画与长截图需要分开判断（已复核，不计故障）

长截图中部分摘要卡片看起来缺失；实际滚动后正常出现。已检查对应可见元素与逐屏截图，不能把它写成“官网大片内容丢失”。建议后续截图基线使用固定分屏和稳定动画状态，同时验证减少动态效果偏好。

证据：[实际中段视口](00-home/home-mid-desktop.png)、[主页第 2 屏](00-home/home-desktop-section-2.png)。

## 4. 学生端

### S01 · 同一账号的“当前学习”缺少一致表达（P1）

“今天”与 Tutor 展示的当前光学项目进度为 11%；“我的项目”可见列表中的首个光学项目为另一对象，进度为 56%，标题被写成一整段研究主线。它们不是同一个 projectId，**不能简单称为同项目百分比计算错误**；问题在于“当前项目”的选取规则和列表对应关系对用户不透明。

建议：由现有服务端 owner 明确当前项目，并在列表标记“当前学习”；卡片上用短项目名，原研究主线作为摘要。可见数字注明任务完成口径和更新时间；不要用前端修补百分比掩盖不同对象。

证据：[今天](02-student/today-desktop.png)、[项目列表](02-student/projects-mobile.png)、[当前项目详情](02-student/project-detail-desktop.png)、[列表首项目详情](02-student/project-from-list-desktop.png)。

### S02 · 个人画像的身份与证据解释存在明显疑点（P1）

当前账号显示演示学生，画像标题却显示另一姓名与学校；画像呈现 86.5 的综合指数、3 个交付项目、36 项证据和 142 轮启发，而成长轨迹显示尚无记录。截图已遮蔽姓名/学校。不同投影可能有独立口径或更新时间，现有 UI 没有给出足够解释，本次也未核验这些数字的生成依据。

建议：先核对账号与投影对象、演示/真实来源和版本时间；有证据才展示能力分数、同学段比较和徽章，否则显示“证据不足/待生成”。每个结论连接可授权查看的证据摘要。不要把截图中现成的数值写成产品有效性结论。

证据：[画像](02-student/profile-desktop.png)、[成长轨迹](02-student/growth-desktop.png)。当前仓库的画像代码使用 API 数据，这不等于线上截图的版本已经与其一致。

### S03 · Tutor 同时展开的面板过多（P1）

1440px 桌面同时显示全局导航、会话历史、对话主区、项目与课时侧栏。光学预览在对话内实际只有约 439px 宽，复杂可视化和公式难以舒展。手机上顶部身份/团队说明、状态按钮、会话条继续占据较多高度；快捷提示条需要横向移动。

建议：保持七项主导航，进入 Tutor 后按视口默认收起非当前所需面板；项目/团队详情通过现有侧栏开关渐进展开。手机优先保证当前教学动作与输入框，在真实软键盘下验证 `visualViewport` 和底部安全区。截图中聊天区空白是隐私遮蔽，不能据此判断 Tutor 没有输出。

证据：[Tutor 桌面](02-student/tutor-desktop.png)、[Tutor 手机](02-student/tutor-mobile.png)、[光学模型预览](02-student/optics-preview-desktop.png)。

### S04 · 学习界面暴露内部合同词汇（P2）

会话列表显示 `intent_confirmed`；灵感页出现 `physics_optics`，模板说明使用“检查点不自动产生掌握或作品通过事实”等工程语言。学生需要理解的是正在探究什么、当前证据说明什么、接下来做什么。

建议：建立状态和学科显示词典，转为“已确认方向”“光学探究”等；技术版本、绑定、工具轨迹保留在适合排障的折叠信息中。不能为了简化文案而伪造“已掌握”或取消安全门禁。

证据：[Tutor](02-student/tutor-desktop.png)、[灵感空间](02-student/inspiration-desktop.png)、[推荐详情](02-student/recommended-detail-desktop.png)。

### S05 · 空态和封面占位影响下一步行动（P2）

项目列表的空封面占据较大面积；长标题在手机上需要多行。今天页在已有进行中项目时提示“当前阶段任务已经完成，明天再来看看吧”，但本次未验证服务端已确认阶段完成，空任务本身不应自动推出完成事实。

建议：无封面时使用紧凑学科图标与项目摘要；标题限制展示行数并支持展开；无今日任务时可提示“今天暂未安排任务”，提供返回当前项目或与 AI 搭档讨论的已有入口。

证据：[项目手机](02-student/projects-mobile.png)、[今天桌面](02-student/today-desktop.png)。

### S06 · 独立工作台出现错误边界（P1）

访问当前项目的 `/workbench` 路由，两次得到“工作台加载失败 / 页面渲染时出现了问题”，并显示数字错误摘要。它是源码存在的独立路由，本次不是从当前可见主按钮进入，因此其优先级应结合是否仍被外部链接使用确认。

建议：检查兼容入口的真实 owner 和部署版本；仍支持则修复渲染，不再支持则受控返回现有项目视图并保留对象上下文。错误页保留重试，并增加“返回项目”与可复制诊断编号。

证据：[工作台错误](02-student/workbench-route-desktop.png)。没有观测到与该错误直接对应的 HTTP 4xx/5xx，不能据此归因为 API 失败。

### S07 · 日期使用 UTC 截日（P1）

本次本地时间已到 10 月 21 日凌晨，“今天”显示 10 月 20 日。源码 `apiTodayDataSource.ts` 使用 `new Date().toISOString().slice(0, 10)`，与观察一致。

建议：由产品明确学校/账号时区；日期按该时区计算，不从 UTC ISO 字符串截取“今天”。验收至少覆盖中国时间 00:00–08:00 的边界。

证据：[今天截图](02-student/today-desktop.png)、[日期生成源码](../../apps/student-center/features/today/data/apiTodayDataSource.ts)。

### S08 · 光学模型预览边界清楚，默认值仍需优化（P2）

预览明确标注“计算示意”“正式实验运行与观测保存尚未接入”，没有把它作为实验成功证据。默认散射参数却立即显示“超出本预览的瑞利近似域”，与“瑞利蓝天散射”预设名称形成体验上的冲突。

建议：从批准的模型域中选择有效默认参数，域外状态保留清晰解释；预览、模拟观察、正式证据保存继续分开。未点击预测、运行或记录观察，本次不评价数值精度或正式门禁接口。

证据：[光学预览手机参数与域提示](02-student/optics-preview-mobile-part-4.png)、[完整分屏索引](02-student/README.md)。

## 5. 班主任端

### T01 · 工作台的统计口径不自洽（P1）

工作台顶部“待处理问题”为 0，关注学生卡却标记 1 个待处理问题；学生管理页顶部也显示 1。工作台“进行中的项目”为 2，阶段分布全部为 0。可能是统计范围、演示来源或刷新时间不同，但当前页面没有交代。

建议：统一查询口径和投影时间；确属不同范围则在标签和说明中标清。缺失/未接入的分布应显示“尚无可统计数据”，不能与真实 0 混用。

证据：[工作台](03-teacher/dashboard-desktop.png)、[学生管理](03-teacher/students-desktop.png)。

### T02 · 详情密度与移动表格削弱处理效率（P1/P2）

学生管理使用列表加内部滚动详情；基本信息、学习统计、监护信息、协作记录并列堆积。手机的最近活跃学生表格需要横向查看，关键状态列不在初始可见区域。

建议：详情优先显示关注原因、必要证据与可用处理入口，再折叠 Agent 轨迹；手机用同一路由内的紧凑卡片或明确滚动提示，固定身份/状态列。保留现有四项业务导航，不新增“知识库”主导航。

证据：[学生管理](03-teacher/students-desktop.png)、[手机工作台](03-teacher/dashboard-mobile.png)、[教师滚动详情](03-teacher/README.md)。`/teacher/knowledge` 本次回到工作台，属于兼容行为，不能当作已上线第五个模块。

## 6. 家长端

### P01 · 孩子选择器与首页项目内容冲突（P1）

选择器显示“0 个进行中项目”，首页却同时显示当前植物观察项目和 40% 进度。页面有“演示数据”标识，这是正面做法；仍需说明不同卡片的数据来自哪里。

建议：选择器和主内容消费相同孩子上下文与明确的统计范围；换孩子时保持最新请求优先，旧响应不能覆盖当前孩子。没有通过延迟注入验证竞争条件，不能把这一要求写成已经失败的线上缺陷。

证据：[家长首页](04-parent/home-desktop.png)。

### P02 · 手机消息页的桌面布局语义残留（P2）

手机上四张统计卡依次竖排，占据消息列表之前的大段高度。消息详情提示仍为“请选择左侧消息查看详情”，但消息列表在上方；下方服务工单表格仍有横向查看成本。

建议：统计改为紧凑双列或一行摘要，优先展示待确认项；提示改为“选择一条消息查看详情”，选中后在同页展示详情并提供返回列表。未发送反馈或点击已读确认。

证据：[消息手机](04-parent/messages-mobile.png)、[消息桌面](04-parent/messages-desktop.png)。

## 7. 管理端

### A01 · 双导航与授权矩阵的可用空间不足（P1）

全局侧栏加设置侧栏占用较多宽度；工具矩阵在 1440px 下仍需横向查看，行列全选操作密集。手机将多个设置项置于横向条，后面的入口不易发现。局部表格滚动本身合理，问题是当前角色、列位置和批量影响不够容易追踪。

建议：保留现有分组和顺序，增加当前分组定位、快速检索、窄屏目录抽屉；矩阵固定行名与表头、清晰提示横向滚动，并展示受影响项数量。更改保存反馈仍必须遵循幂等 PATCH、真实回读和部分失败规则。

证据：[工具矩阵](05-admin/tools-desktop.png)、[设置手机](05-admin/settings-mobile.png)、[技能矩阵](05-admin/skills-desktop.png)。

### A02 · 管家默认控制值与主要任务不易理解（P1）

当前管家首屏同时展示助手、团队、思考强度、模型和权限；截图中的模型为 `gpt-image-2`，权限标为“Full Access（完全访问·免确认写入）”。本次没有发送管家指令，因此只确认展示状态，不能确认实际调用了该模型或实际拥有这些写权限。

建议：会话默认模型应由 Admin 配置按能力适配并由服务端校验；保留 `(modelProviderId, modelId)` 身份。前台默认显示完成任务必需的选择，其余折叠；权限文案应解释可影响的配置范围和实际后端限制。目录读取失败时不保留误导性的成功状态。

证据：[管家桌面](05-admin/copilot-desktop.png)、[管家手机](05-admin/copilot-mobile.png)。

### A03 · 本地化、术语和功能成熟度表达不一致（P2）

飞书页同时出现 “Feishu manager bot / Application and assistant / Phone QR binding”；设置页混用英文大写眉题、emoji、描边图标、实现说明和不同风格的状态标签。管理员需要技术信息，但不需要在每个区域反复阅读同一层级的实现说明。

建议：中文作为主要操作文案，英文接口名用于补充；状态统一为“草稿 / 已配置 / 已启用 / 未核验 / 最近失败”，把“目录存在”与“真实请求成功”分开显示。重要限制保持可见，调试说明可折叠。

证据：[飞书设置](05-admin/feishu-desktop.png)、[模型接入](05-admin/model-providers-desktop.png)、[数据库](05-admin/database-desktop.png)。

### A04 · 总览存在可减少的重复与留白（P2）

部分页面在全局页头与正文重复同一标题；治理概览中的六张大指标卡信息很少，设置总览还有一块高宣传式介绍。高频管理员必须滚动后才能到具体配置。

建议：页头负责当前位置，正文直接给关键状态和动作；压缩纯数字卡片与介绍高度；保留分组、顺序及导航名称，避免借视觉优化进行未评审的信息架构重构。

证据：[治理概览](05-admin/overview-desktop.png)、[设置总览](05-admin/settings-desktop.png)。

## 8. 跨端视觉与可访问性

蓝白色调、机器人形象和圆角方向值得保留。建议集中修正以下共性：灰蓝小字的可读性；默认蓝色下划线链接与按钮混用；emoji 与线性图标混排；同级标题和卡片内边距不一致；无封面和无数据状态过高；小型关闭、展开、工具控制缺少足够触摸空间。

DOM 检查统计了无名称控件和小于 24px 的目标候选，但没有完成可访问名称计算、间距例外、对比度逐像素测量或读屏测试，**这些候选数不能当成 WCAG 失败数量**。本次截图也没有验证软键盘、200%/400% 缩放、Safari、Android 真机或所有深浅主题。

后续可按 W3C 的 [重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)检查窄屏内容和二维表格的例外；按 [目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)核对 24×24 CSS px 或允许的间距/内联等例外；按 [文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)验证普通文字 4.5:1、大字 3:1。项目自身可将主要手机操作的设计目标定为 44px，这不是把 WCAG AA 最小要求改写成 44px。

## 9. 结论适用范围

这是一次线上视觉与有限交互审查，不是权限渗透测试、模型质量评测或生产验收。中途浏览器的指针点击未稳定触发 React 事件，改用 DOM click 完成部分展示操作；没有将该自动化现象判成前端按钮失效。主要入口、页面状态和视觉结论有截图支持，写入、竞态和完整键盘可用性仍需后续行为测试。
