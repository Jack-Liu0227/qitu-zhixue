# 一滴雨的项目旅程（#56）

## 设计边界

首页主张是「一个问题，长成一件作品」。采用白垩底色、钴蓝主色、深蓝文字与有实体质感的校园模型，替代粒子、光晕和虚构进度。公开站点用衬线展示标题，角色工作区用清晰的中文无衬线正文。保留所有冻结导航、数据来源、状态门与权限合同；不把首页视频搬进业务工作区。

五个应用根布局最后导入 `@qitu/ui/brand.css`。核心 token 在 `packages/design-tokens` 与 UI CSS 中同步维护：页面 `#F4F7FB`、主色 `#0038B2`、标题 `#132646`、正文 `#30435F`、次要文字 `#566780`、边框 `#DDE5F0`。状态色仍表达语义，不强行染蓝。家长、管理端手机抽屉与桌面收起状态独立，切换路由、进入窄屏与 Escape 关闭抽屉。

## 故事与六幕剧本

故事：「让校园的一滴雨，长成一个作品」。同一个校园雨水花园模型、同一高位镜头与日光，逐步增加实验、作品和证据，而不是六张无关插画。

| 幕 | 起点 | 画面 | 学习含义 |
|---|---:|---|---|
| 1 发现问题 | 0s | 校园积水、空花园、测量工具 | 从真实观察出发 |
| 2 自主提问 | 4.4s | 笔记本、草图和问题卡 | 学生确认意图后才创建正式项目 |
| 3 理论验证 | 8.8s | 土壤分层渗透实验 | 理论达标才进入实践 |
| 4 动手制作 | 13.2s | 水道、蓝色入水口、透明花园剖面 | 把理解制作成方案 |
| 5 测试迭代 | 17.6s | 量杯模拟降雨、观察水路 | 记录测试并继续改进 |
| 6 反思沉淀 | 22s | 完成模型、过程照片、观察档案 | 授权范围内分享成长证据 |

章节文本、图片替代描述与时间在 `apps/auth-portal/app/home/storyboard.json`。画面不含真实儿童、学生数据、成绩或可识别人物。提示词见本目录 `rain-garden-prompts/`。

## 素材来源与合成

- 按用户指定的本机 ImageGen skill，通过 Python OpenAI SDK 调用 `gpt-image-2` 生成 2048×1152 PNG；凭证只保存在本机 skill 配置，不进入仓库。
- 共生成八幅：六幅初稿，其中第 5、6 幕为保持入水口与透明剖面的连续性，各定向修订一次。最终采用六幅画面。
- PNG 原稿与运行输出保存在被忽略的 `output/imagegen/`，生产仅提交六张 WebP 和 MP4，避免把运行配置或大体积原稿带进仓库。
- `python tooling/build-story-film.py` 使用 Pillow 和 ffmpeg：每幕 5 秒、轻微推近、五次 0.6 秒叠化，合成 27 秒、1280×720、30fps、H.264、无音轨、faststart 视频。存在 `scene-NN-revised.png` 时优先使用修订稿。
- 这是**生成静帧合成视频**，并非原生文生视频，也不是真实学生学习录像。页面明确标注此边界。相邻画面叠化不等于真实流体或物理仿真。

## 播放与可访问性

静态首帧与完整文字优先。支持播放/暂停、六章跳转；选择章节会暂停。系统或产品减弱动态偏好关闭视频源，节流偏好默认静态，需主动播放。离屏、页面隐藏或离线时暂停；视频失败保留分镜、文字与重试入口。无音轨，无自动播放声音。章节按钮、键盘焦点和替代描述保留。

## 验证与风险

- 自动化：`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`；`tooling/brand-story.test.mjs` 随 UI 测试运行，检查六幕资产、时间、叙事门禁、包体预算与五应用共享样式导入。
- 浏览器：使用 Playwright skill、网站自带演示账号，只读检查首页与四角色入口；桌面 1440px，手机/平板 320、375、414、768px。演示截图放系统临时目录，不提交含账号界面的截图或会话凭证。
- 部署后必须实际检查 CSS/JS、六张图片、视频及 Range 请求，而不是只看 HTML 200；执行 `tooling/check-frontend-assets.py` 与线上 Playwright 回归。
- 不增加数据库迁移、API 写接口、模型调用或权限范围。角色页面原有 loading、empty、error、offline 与权限失败流程不变。主要风险为跨应用 CSS 级联与低带宽视频加载，分别通过共享层末尾导入、真实截图和静态降级约束。
