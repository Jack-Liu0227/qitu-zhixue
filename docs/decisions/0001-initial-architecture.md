# ADR 0001：首期工程架构

- 状态：Accepted
- 日期：2026-09-24
- 范围：M0 工程初始化

## 决策

1. 使用 `pnpm workspace + Turborepo` 管理 Monorepo。
2. 四个平台分别作为独立 Next.js 应用，禁止互相导入业务代码。
3. 共享能力放在 `packages/*`，跨端数据类型集中在 `packages/contracts`。
4. 后端使用 NestJS 模块化单体，按领域模块拆分，不提前拆微服务。
5. PostgreSQL、Redis、对象存储和队列通过后端基础设施边界接入；初始化阶段不绑定具体云厂商。
6. 项目状态转换由 projects 领域统一写入，其他模块通过命令或领域事件请求变更。
7. 家长授权、班主任分配、审计和幂等能力属于后端横切基础设施，不能由业务页面各自实现。
8. 第一条端到端业务闭环暂定为：邀请学生 → 登录 → 选择项目 → 创建项目 → 完成理论任务 → 家长看到成长快照。

## 原因

产品包含四个平台、未成年人数据、AI 会话和异步任务。单仓库便于共享合同和统一 CI；模块化单体能保留清晰边界，避免在需求尚未稳定时引入微服务运维成本。

## 明确不做

- 不在 M0 实现完整认证、AI、语音、支付或数据库业务表。
- 不让客户端直接修改项目状态、成长档案或审计数据。
- 不把所有共享代码放进一个 `utils` 包。
- 不使用跨应用相对路径导入业务模块。
