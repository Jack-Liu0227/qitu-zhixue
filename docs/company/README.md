# Company 公司工作区

Company 位于 `/company`，前端代码为 `apps/company-console`，开发端口为 `3105`。它与学生、家长、教师、Admin 共用登录和 API。

## 进入与权限

Admin 可从经营工作区进入 Company。其他非学生账号需要由公司所有者授予成员角色：

主站入口为 `http://122.51.130.204/company`；也可使用官网页脚「公司管理」入口，经共享登录页进入。管理员使用原有 Admin 账号，测试环境可在登录页选择管理员测试账号自动填入。Company 没有另设独立密码。模型、技能与全局教学配置仍从 `/admin` 进入。

| 角色 | 权限 |
| --- | --- |
| owner | 公司配置、成员与群绑定、经营操作、数据查看 |
| operator | 创建工作、查看客户与财务、维护公司知识 |
| analyst / viewer | 查看经营汇总和团队工作成果 |

公司成员权限由后端再次核验。模型供应商、密钥、技能、知识库授权和教学策略仍在 Admin 管理。机构购买不会增加教师权限。

## 工作区页面

| 路径 | 使用方式 |
| --- | --- |
| `/company` | 查看累计经营指标、最近 30 天收款及最近任务 |
| `/company/work` | 委派任务，查看排队、执行、失败和成果，取消或重试 |
| `/company/teams` | 为 12 个公司职能绑定 Admin 中的助手并启用 |
| `/company/customers` | 跟进咨询线索、登记机构、创建试点订单、核对付款及分配学生席位 |
| `/company/products` | 绑定课程目录、保存产品发布状态、启用订阅策略 |
| `/company/finance` | 查看订单与退款、登记实际成本、处理待审核退款 |
| `/company/data` | 按来源和统计口径查看账号、学习、交易、会员和模型汇总 |
| `/company/knowledge` | 保存公司流程、产品说明与经营决策 |
| `/company/integrations` | 管理公司成员，查看飞书连接，绑定群、发送人和公司操作账号 |

Company 工作成果由真实模型请求生成并持久化。每 24 小时最多创建 50 个任务，每项最多 3 次执行，单次输出限制为 4000 tokens。任务失败、租约过期或被取消不会显示为成功。任务使用经营汇总数据，不向模型提供原始学生对话、密码或供应商密钥。

当前工作执行器提供分析、规划和草稿成果；对外发布、退款、部署和学习状态变更不作为模型自由工具执行。公司知识保存与教学知识库授权是不同操作，保存条目不会扩大 IMA 权限。

## 首次初始化

Company 总览提供初始化清单。基础经营、AI 团队、订阅售卖和飞书各自检查准备状态，未配置微信支付不妨碍知识管理或内部工作。

1. 使用现有管理员账号登录，确认 Company 显示公司所有者权限。其他运营账号由所有者在「飞书与集成」中添加公司角色。
2. 在 Admin「助手配置」创建公司专用助手，选择已配置的模型供应商及模型。公司助手只生成内部可审阅成果，无需绑定学生教学技能、外部工具或飞书即可开始使用。
3. 在 Company「Agent 团队」选择对应助手，点击「绑定并启用」。已启用部门更换助手时使用「更新绑定」，停用为独立操作；成功以服务器回读为准。
4. 在「公司知识」保存真实的产品、服务及运营说明。在「工作与成果」选择已启用部门，说明具体目标并委派任务；看到“已完成”和成果正文才表示模型请求成功，单纯绑定成功不代表执行成功。
5. 收款另按下述售卖步骤配置；飞书可选，按下述群绑定说明配置。没有真实商户、合同或收款记录时，不用虚构资料填满后台。

初始化不修改已有教学助手、学习门禁、账号关系或已购权益。公司专用助手不加入教学团队可选列表；模型仍在 Admin 统一管理。公司知识条目当前供人工查阅，不会自动作为每项任务的知识检索范围；需要引用时将必要的非敏感内容写入任务说明。

## 内部运营巡检

进入 Admin「平台设置 → 经营工作区」（`/admin/settings/ops`），选择「项目包与服务」，在「运营检查」中启用每 5 分钟检查并保存。咨询跟进时限默认 24 小时，开通后尚未开始的关注时限默认 7 天，可按实际服务约定调整。

巡检检查超时咨询、待处理退款和符合条件的课程订单，生成的待办在「客户与待办」中处理；「经营总览」可查看最近检查时间并立即检查。保存后重新读取页面，确认开关、阈值和最近检查时间。停用时取消勾选并保存，已有待办和审计记录保留。

这项巡检按服务端规则执行，不调用公司 AI 助手，也不自动退款或向客户、飞书发送消息。Company「公司知识」可保存巡检说明和后续配置清单；实际开关及阈值以 Admin 的服务器回读为准。

## 开通订阅售卖

1. 在 Admin 配置经营主体、客服、服务条款、隐私和退款规则，以及现有微信 Native 支付商户配置。
2. 发布可售教学版本并绑定有效教学团队。体验课必须是独立的 1 课时、20–30 分钟版本。
3. 在 Company 产品页为体验课、月会员和试点选择目录；月会员目录应包含体验课版本。
4. 选择免费入门版本，保存产品后启用订阅策略和经营销售开关。默认均不自动开放。
5. 由家长为已绑定孩子创建订单，获取微信付款码。以验签回调或查单核实付款后开通权益。

基础版为每天 10 次基础问答、1 个免费入门项目。体验课 990 分、7 天、100 次交互，每生限购一次；7 天内首次升级月会员可抵扣实际体验支付金额。月会员 39900 分、每个会员月周期 1500 次有效交互，续费衔接已有服务结束时间；系统不自动扣款。AI 内部调用、自动开场和失败回合不重复计费。

机构试点为 298000 分、30 天、30 名学生，每生指定课程 100 次交互。席位由 Admin 分配，唯一学生重复分配不重复占位。机构课内优先使用机构额度，家庭探索使用个人额度，不把两个额度相加。

年卡、机构标准版和学校版可查看条件性报价，服务端阻止发布售卖。需另行完成收款周期和业务要求确认。用户已开始的历史项目包与已有学习记录保留；订阅只控制商业使用资格，不改变理论掌握、作品评价或学习事实。

会员退款按实际支付金额和未履行服务时间计算，未来尚未开始的周期可全退。退款额度在申请时冻结；原路退款成功回执后才撤销对应权益。已用于会员优惠的体验订单先处理关联订单，避免退回已经抵扣的金额。服务异常或零剩余期间的争议由客服核实。

## 飞书群绑定

在 Admin 为一个规范助手配置飞书应用机器人并启用事件接收。再在 Company 绑定应用 ID、群 Chat ID、发送人 Open ID、对应公司用户 ID 及部门。不要把 App Secret 放进任务内容或群消息。

群内命令示例：`/company data 请分析本周经营数据`。同一个机器人、群和发送人可以分别绑定多个部门。只有已绑定的应用、群、发送人和有效公司操作账号组合可以创建任务。普通群成员、机器人消息、其他应用及其他群不能获得权限。撤销绑定或公司角色后立即阻止新任务。

群里只回传任务 ID 与完成状态，详细成果留在需要登录的 Company 页面；发送成功以飞书消息回执为准。机器人加入群、长连接建立、收到事件、任务完成与消息送达是不同状态。

协议参考：[飞书发送消息接口](https://open.feishu.cn/document/server-docs/im-v1/message/create)、[微信退款开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4013071031)。

## 部署与维护

按仓库依赖顺序构建合同、数据库与 API，并执行 `0056_company_commerce` 迁移后再启用新界面。数据库变更只增加新表和订单扩展字段，历史订单不会被重写为会员。

构建前端：`pnpm --filter @qitu/company-console build`。使用 [systemd 示例](../../tooling/qitu-company.service) 与 [Nginx 路由示例](../../tooling/nginx-company.conf.example) 接入已有站点；`/company` 前缀必须保留，`/api` 继续使用共享后端。启动脚本支持 `company` 服务，端口由 `QITU_COMPANY_PORT` 配置。

使用 `node tooling/verify-company-commerce.mjs` 验证源码依赖和类型。Windows UNC 安装可能包含复制的依赖快照；验证脚本使用独立构建输出。运行隔离数据库检查时，`QITU_BUSINESS_FIXTURE_URL` 只允许非 5432 的本地测试实例；不得指向生产数据库。

常用错误码：`COMPANY_ACCESS_DENIED`（角色不足）、`COMPANY_TEAM_NOT_READY`（助手未启用）、`COMMERCE_QUOTA_EXHAUSTED`（周期额度耗尽）、`COMMERCE_TRIAL_COURSE_REQUIRED`（体验教学版本不匹配）、`COMMERCE_CONDITIONAL`（条件性方案）、`COMMERCE_LINKED_REFUND`（优惠关联退款）。
