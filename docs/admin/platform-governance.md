# 平台治理（管理端总览）

> 文档基线：`2026-10-19`，版本标识：`v2026.10.19`。
> 治理原则：**后台控制权全在 Admin**。所有模型底座与提供商网关（Model Providers / Model Gateway，默认启途运行时引擎）、运行时技能矩阵（Runtime Skills）、项目与课程模板生命周期、知识库/IMA 范围及全平台策略配置由 Admin 后台集中收口控制，客户端不得自行路由或越权覆盖。
>
> 管理端是平台治理控制面，默认展示聚合指标、权限关系、模型供应商、AI 运行时和初始化状态，不承担班主任的日常学生处理。

## 页面与导航

`apps/admin-console` 使用 `basePath: '/admin'`。设置入口保持冻结：

| 导航         | 实际路径                     | 说明                 |
| ------------ | ---------------------------- | -------------------- |
| 治理概览     | `/admin`                     | 平台总览和聚合指标   |
| 学生数据统计 | `/admin/students/statistics` | 聚合治理投影         |
| 关系绑定     | `/admin/relationships`       | 监护关系和班主任分配 |
| 设置         | `/admin/settings`            | 设置索引和子导航     |

设置子页面包括：

- `/admin/settings/ai-runtime`：AGENTS.md、Skills、模型、Tools、MCP、Agent 配置和初始化检查。
- `/admin/settings/assistants`：助手目录、启用状态和 Agent 直接模型选择。
- `/admin/settings/teams`：团队成员、协同 route 开关和真实 Team Run 测试。
- `/admin/settings/model-providers`：供应商凭证、模型目录、连接测试、用途场景和 Agent 链路绑定。
- `/admin/settings/models`：旧书签重定向到供应商工作区，不单独保存模型目录。
- `/admin/settings/knowledge`、`templates`、`database`：知识、模板和数据库状态。
- `/admin/settings/feishu`：管理员汇报助手的 Feishu/Lark 机器人配置、手机授权状态和汇报范围；该页面不保存明文凭证。

旧的 `/admin/settings/dialogs`“已安装的对话”静态原型入口已退役。真实对话开场由冻结模板、团队绑定和 AI Tutor 上下文生成；不保留第二套浏览器本地对话流、安装记录或兼容配置。

模型专属覆盖在 AI 运行时维护；用途模型和链路自动分发在供应商工作区维护，不增加导航。管理员明确选择用途后才清空专属覆盖；学生不能自由换模。

## 权限与数据边界

团队、助手、模板库、知识库、模型供应商、模型、运行时 Agent、MCP 与知识引擎配置遵守同类别名称唯一规则；创建和重命名均由服务端校验，并使用数据库约束防止并发重复。停用和归档不释放名称，模板保留学校作用域，模型按供应商区分。冲突返回 `RESOURCE_NAME_CONFLICT`，具体范围、迁移和历史数据处理见[名称唯一规则](../../Plan/issues/20261026-resource-name-uniqueness.md)。

项目模板的教学编排在原设置页按课时配置：直接选择团队管理中的已有团队及其助手，或由该团队负责人主讲，无需手动发布或选择团队版本。保存时服务端自动记录不可变团队配置，旧项目不随新安排改变；已校验或已启用配置通过新安排重新编排。团队负责成员管理，课程模板负责教学流程，没有独立 PBL 工作流的启用团队也可以用于课程。四阶段保留为已有状态和门禁的兼容层，不再限制教学者按四组分配。详见[课时级助手与团队绑定](../../Plan/codex/template-session-bindings-20261023.md)。

2026-10-24 用户明确要求精简模板页：列表只显示领域、名称、简介、有效教学配置中的课时/时长与课程入口，素材和删除放入更多操作。进入课程后只保留一个“教学编排台”：左侧课时目录，中间当前课时内容与教学者，右侧导师能力、教学方法和团队成员。移除独立“课程版本发布”区块、重复课时列表及宏观参考视图；基本信息、版本记录、质量核验、JSON 和历史恢复合并到编排台的高级设置。上架状态显示“已上架”，新配置显示准确的待配置/待启用状态，保存、校验、权限与历史冻结约束继续由原服务维护。产品导航和路由不变。

- 前端只负责显示；所有 Agent、供应商、模型和对象级权限由后端再次校验。
- 涉及未成年人数据时默认最小化可见范围，并保留审计记录。
- 密钥、MCP 凭据、完整系统提示词和未成年人原始对话不进入治理投影。
- 数据库不可达或状态无法证实时返回 `unknown` / `unavailable`，前端不得推断为已就绪。

## AI 运行时

运行时页面集中展示根目录 `AGENTS.md`、已加载 Skills、Agent-local `AGENTS.md`、直接选择的供应商与模型、显式 Skill/Tool/MCP 绑定和初始化检查。开发协作目录（例如 `.pi`）不自动进入 Tutor runtime。

Agent 写入使用 Admin-only API、幂等键、事务和审计。子 Agent 不默认继承 Tool/MCP；Skill 继承必须显式声明。模型调用前服务端重新解析 Agent 配置，客户端不能直接写入模型决策、项目状态或成长档案。

### Feishu/Lark 管理汇报助手

Feishu 只是外部通知渠道，不是新的权限边界。管理员配置、二维码会话、凭证轮换和发送状态均由服务端持久化并审计；`open_id` 必须映射到启途管理员后才能生成报告。报告助手只读聚合学生、家长授权投影和教师运营摘要，默认最小化可见范围，禁止发送原始未成年人对话或语音。手机扫码绑定、状态机、错误码和真实租户验收的当前台账见 [`../plan/20261018-issue-digest-feishu-assistant.md`](../../Plan/20261018-issue-digest-feishu-assistant.md)；[2026-10-17 早期方案](../../Plan/archive/pre-20261018/plan/20261017-feishu-reporting-assistant.md) 仅作历史参考，不代表真实租户验收通过。
QR session recovery, provider-controlled expiry, permissions, audit events and regression coverage: [Feishu QR binding](../../Plan/diagnostics/feishu-qr-binding.md).

按助手独立绑定、双向消息、实际连接诊断、权限复核与 0044 发布要求见 [飞书机器人与助手消息绑定](./feishu-assistant-messages.md)。

### 知识库与 JSON 配置树

当前知识相关配置统一位于“知识库”下，ima 作为知识引擎实例纳入其中。JSON 工作台保留原双卡布局，子工具可展开查看真实参数；目标映射、管理员目录接口及未提供 schema 的状态边界见 [工具与 MCP JSON 配置树](./mcp-json-tree.md)。统一配置以 `platform-config` 修订为准。

### 历史 ima 集成兼容说明

以下记录旧版 ima 专用接口与迁移背景；当前配置入口与项目检索治理以知识中心及上述统一配置树为准。

`设置 → 工具与 MCP` 的 ima 总开关、助手授权矩阵、运行时 Agent 绑定、JSON 编辑及预览均读取服务端配置。`GET/PATCH /api/v1/admin/ai-runtime/mcp/ima-knowledge` 只向管理员开放；写入必须携带幂等键，并在事务内审计。`POST .../check` 实际完成 MCP 握手并读取知识库清单；连接正常与允许调用是两个独立状态，关闭总开关仍可检查连接。

学生 Tutor 必须同时通过全局开关、运行时 Agent 工具白名单、当前阶段助手授权和角色启用检查；每次新工具请求前重新查库，已发现的工具也不能绕过撤权。已发出的上游请求可能完成。数据库异常时拒绝调用。此配置不修改助手启停、模型绑定或教学门禁。

浏览器 JSON 仅允许 `enabled`、`assistantBindings`、`agentBindings`，不接受地址、命令或凭证。连接参数和 ima 密钥保留在服务器配置中，响应不含密钥或上游原始错误。旧页面的本地 MCP 草稿不再被当作已连接服务，不修改或删除其浏览器存储。

新增工具、MCP、Skill、助手和团队必须进入服务端注册表或配置库，并提供真实状态、授权绑定和失败状态；只写浏览器存储不算完成接入。设置总览与工具页能力清单读取后端状态，不能用默认数量或模拟延迟宣称就绪。

升级已部署的 ima 集成时执行 `tooling/migrate-ima-admin.sql`，一次性保留既有阶段导师的访问授权；迁移审计键防止重跑后覆盖管理员撤权。该迁移不启用已停用的助手，不修改任何模型。新助手默认无 ima 授权，管理员须在矩阵明确授予。

验证：API 单测覆盖管理员权限、字段白名单、敏感信息脱敏、全局/角色/工具/阶段授权和数据库异常；MCP 客户端测试覆盖工具发现后撤权不向上游发请求。发布时还需验证真实连接、开关刷新持久化、JSON 保存、矩阵撤权和桌面/移动端页面。

### 知识库卡片选择与助手绑定

2026-10-22 已确认调整为“上方知识库配置、下方助手 × 知识库矩阵”，参见[实施方案](../../Plan/codex/knowledge-center-config-matrix-20261022.md)。矩阵是逐库助手授权的主要编辑入口，配置抽屉不再重复编辑授权。保存为有修订保护的增量 PATCH，逐库返回结果并回读；现有全局停用、对象权限和项目冻结范围仍限制实际访问。以下逐库选择说明记录旧版交互。

知识库页提供“一键检测远程知识库”，检测全部远端连接，不受搜索或引擎筛选影响。复用 Admin-only 的逐库真实检查接口，最多并发两项，并逐库展示检测时间、错误码、认证/授权异常、资源不可访问、网络异常或通过。请求或回读中断不显示为通过，未确认请求使用原修订号和幂等键核验。检测不修改凭证、资源关联、助手授权或项目冻结范围；认证被拒绝不能直接判定为凭证过期。检测期间暂停本页配置和矩阵写入，未保存草稿保留，修订冲突需重新读取并核对后保存。详见[结果说明与发布回执](./knowledge-connection-checks-20261022.md)。

知识库卡片左上角显示选择框，单击卡片选中一个知识库，双击打开详情；键盘空格选择，Enter 打开。列表下方的“检索助手绑定”始终显示当前选中库的助手，而非平台整体检索权限。未选择时显示引导，读取失败支持重试。勾选或取消后点击“保存助手绑定”调用逐库绑定接口，沿用修订校验、幂等与权限控制，并保留其他类型 Agent 的绑定。切换库丢弃未保存草稿；快速切换不得显示上一个库的延迟响应。全局工具开关和助手启用状态仍限制实际检索。

### 全站素材库与默认展示

Admin 在现有助手、团队、模板、知识库编辑位置选择共享素材；外观设置集中维护默认值。新助手可直接继承默认，已有定制头像保留；批量选择逐对象返回结果，保存后回读确认，只重试失败项。素材 ID 只表示外观，不改变 canonical skill ID、模型 pair、团队角色或教学门禁。

素材目录及绑定接口位于 `/api/v1/admin/visual-assets`，仅管理员可访问。写入执行对象存在性、用途与版本引用校验、修订冲突、幂等和事务内审计；持久化需要 0043 迁移。首批素材为已生成的公开内置文件，上传和在线生图尚未开放。源码范围、错误码、浏览器测试和生产发布边界见 [素材库实施记录](../../Plan/codex/visual-assets/04-implementation.md)。

## 管家删除二次确认

管家对话内列出待删除对象、实际操作参数、影响范围和有效期，管理员逐项选择“确认删除”或“取消”。计划生成及普通重试不会执行删除。确认由专用接口提交，绑定当前管理员、原始请求、操作参数和资源快照，有效期十分钟；版本变化、过期、撤销权限或引用保护均拒绝执行。确认与取消记录保存在现有持久化幂等日志并写审计。批量删除逐项确认，模型文本不能替代管理员点击。

管家内“导入知识库资料”在全局配置及完整权限下可用，文件直接提交知识库上传服务并回读构建状态，正文不进入模型或对话历史。通用 MCP 调用同样逐项确认，防止远端删除工具绕过确认；学生侧权限仍由冻结教学包及当前授权控制。

## 模板团队配置与历史会话恢复

2026-10-26 修订：归档课程的“更多”菜单提供“删除课程”。管理员可核对影响清单、勾选删除关联学习数据并输入完整课程名称，永久删除课程全部版本、质量验证记录及关联学生项目、计划、作品、对话和成长记录。曾上架但已归档的课程同样支持；在架课程须先归档。范围变化要求重新核对，失败整体回滚；其他课程、学生账号及审计保留。回读课程不存在后移除卡片。见[课程及关联学习数据删除](../../Plan/issues/20261026-template-cascade-delete.md)。

归档课程在项目模板库的“全部课程”中提供“恢复并编辑”，归档详情顶部也提供该入口。仅管理员可以恢复；恢复基于当前修订，复用幂等键并回读结果。服务端在同一事务中保留历史版本、复制最新内容为新的可编辑版本、将课程恢复到编辑态并写审计；原课程没有版本时保留为空。恢复不会自动上架、启用旧绑定或改写学生项目，新版本须重新完成教学安排与现有上架/发布检查。API 为 `POST /admin/project-templates/:id/restore`，修订或状态冲突返回 `TEMPLATE_RESTORE_CONFLICT`。见[归档恢复说明](../../Plan/issues/20261024-template-archive-restore.md)。

模板编辑器在教学编排区域选择已有团队和每课主讲者，团队成员与助手能力分别在团队、助手管理中维护。课程版本与教学安排状态展示给管理员，团队快照由服务端自动维护。地址保留所选模板和课程版本。保存未变更的课程不生成新版本。保存教学安排必须完整回读后确认成功；仅读取该安排引用的团队快照，历史快照校验失败会明确提示，管理员可重新选择现有团队建立新安排，不会因为无关历史版本异常而禁止配置。

`POST /admin/project-templates/:id/versions/:versionId/bindings/:bindingId/prepare` 根据已发布团队快照、明确课时排期和阶段成员生成草稿。模板未指定助手时，管理员须从实际团队成员中选择；不能按名称或 ID 规则猜测。生成不等于启用，默认不授予知识库范围；之后仍须经过原服务的编译、校验与启用。

管理员可读取同一绑定入口的 `GET .../bindings/project-recovery`，只返回项目 ID 与配置状态，不返回学生身份、原文或学习证据。`POST .../bindings/:bindingId/projects/:projectId/reconfirm` 仅接受修复原因，使用当前有效且编译通过的绑定，按实际项目与模板版本核对范围；完整正式快照不可替换。仅历史回填或缺教学摘要的旧快照可经明确确认修复，幂等且与 `project.binding.reconfirm` 审计同事务。状态冲突返回 `PROJECT_BINDING_CHANGED`；缺教学包返回 `PROJECT_TEACHING_BUNDLE_UNAVAILABLE`；完整冻结配置返回 `PROJECT_BINDING_ALREADY_FROZEN`。该治理命令不授予管理员读取个别学生内容的权限。

管家模型选择保存到既有 `admin.copilot` 用途，保存供应商与模型的组合并回读确认。未设置专用默认时说明当前平台回落来源，可点击“设为默认”固定当前选择。验证与生产配置边界见[修复记录](../../Plan/codex/configuration-binding-recovery-20261021.md)。

独立历史团队版本的列表、发布接口和管家操作已移除。0050 将历史项目引用的团队配置迁入 `pbl_template_team_bindings.team_snapshots`，删除旧表；新安排直接捕获所选团队配置。v1 合同内部标识及原摘要保留兼容，不能作为独立资源选择。迁移与验证见[移除团队版本资源](../../Plan/issues/20261023-remove-team-version-resource.md)。

团队详情展示其关联模板、版本、绑定状态和项目引用计数，支持跳转到具体模板版本。管理员可直接删除当前团队配置；已冻结的课程、绑定和项目快照仍保留并继续运行，后续新编排需重新选择现存团队。删除不自动停用课程或删除助手。权限、幂等、修订校验和同事务审计仍由服务端执行，详见[团队删除与模板关联](../../Plan/issues/20261026-team-deletion-template-links.md)。
