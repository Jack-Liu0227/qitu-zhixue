# Template teaching arrangement

This presentation update stays inside the existing template library. It does not
change platform navigation or silently update historical projects.

The primary task is to inspect which published team member teaches each actual
phase/lesson, which frozen provider/model pair and canonical skills are available,
and what tools, MCPs and knowledge scope are authorized. The normal workflow uses
structured controls; JSON is an advanced representation of the same draft.

Saving a draft, validating it and activating a binding are separate confirmed
operations. A team publication is not proof that a teaching binding is active.
Success requires the existing backend owner's response and matching readback.
Disabled resources and catalog failures are not bypassed or silently removed.

Models and skill packages come from the selected immutable team version. The
template UI can narrow permitted capabilities, not expand the frozen version.
Knowledge permissions are the intersection of the binding and current Admin IMA
grant. An empty knowledge scope means no library access.

Historical recovery remains a per-project, reasoned owner operation for missing
or legacy snapshots. It is not a chat restore tool and does not replace valid
frozen bindings, create mastery or approve artifacts.
