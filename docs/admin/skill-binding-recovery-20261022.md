# 光学模板 Skill 绑定修复

本次修复针对光学模板对话的 `PROJECT_TEACHING_SKILL_UNAVAILABLE`。已发布团队固定了旧 Skill 包摘要，当前 canonical 包已经更新；直接重启或修改现有绑定的 hash 不能恢复正确的版本关系。

## 配置修复路径

通过 Admin owner API 读取当前助手、团队成员、模型、工具和旧教学包。发布新团队版本后，从服务端返回的成员快照取得真实 Skill pins，创建新的模板绑定，再保存教学草稿、编译、校验、激活并回读。各步使用稳定幂等键。

保留课程正文、16 课时路由、角色、canonical Skill ID、模型提供商及模型对、工具和知识库范围。新团队版本和新绑定拥有独立 ID；不覆写旧团队、旧教学包或旧项目快照。有效冻结的旧项目不能借用历史缺失绑定修复接口换绑。

团队发布、绑定编译、校验及激活继续由既有 owner 记录审计。新绑定通过后，新建的模板探索及学生明确确认的新项目才使用它。既有冻结项目恢复需要单独审核迁移，不能在读取时自动采用当前 active 绑定。

## 代码修复

旧运行时仍包含单包 8,000 字符、聚合 24,000 字符及原始文件长度限制。较长的已发布教学包因此被截断或阻止发布，与当前 Skill 合同不一致。移除这些固定上限及 API、worker 中对应调用；实际模型容量错误仍由模型运行时按真实请求返回。

准入继续检查 canonical ID、完整 frontmatter、运行范围、发布及撤销状态、references 路径、真实包摘要和当前对象/工具权限。助手不获授新的 Skill 或工具，知识范围不扩大。停用、撤权和 hash 不一致仍拒绝执行。

`ASSISTANT_SKILL_BUDGET_EXCEEDED` 不再作为固定字符上限的错误。`ASSISTANT_SKILL_UNAVAILABLE`、`PROJECT_TEACHING_SKILL_UNAVAILABLE` 及团队、教学包的摘要和权限错误继续生效。

worker 的既有投影测试还发现，组合输出合同中的 `allOf` 路由限制此前没有执行。补上递归检查，继续拒绝不符合原路由 Schema 的候选。对应测试按当前闭合合同，在出现额外私密字段时验证明确拒绝及错误内容最小化。

## 验证范围

`node tooling/verify-tutor-lessons.mjs --current` 覆盖既有课时与活动 owner、真实角色完整 Skill 加载、目录准入、团队发布及冻结版本隔离。另运行 model-runtime Skill 包测试与 worker 测试，检查长正文和 references 完整加载、撤权、越界路径及结构化任务边界。

线上验收使用合成测试账号，从灵感空间进入模板，检查对应开场白、真实模型 SSE、动态课件工具、团队状态、学生明确确认后的冻结绑定和实际 16 课时投影。测试产物由原 owner 清理。

这次绑定修复不表示新版逐课教学合同已经发布，也不证明知识库、全部课时评价及完整课堂流程已经验收。
