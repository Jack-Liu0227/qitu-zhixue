日期：2026-10-29。状态：提交准备与服务器验证中。

用户授权提交本地变化文件，先推送 study-remote 并完成服务器测试，通过后推送 GitHub，使三端同步。

## 范围

包括现有注册与登录、问答学习、课程交付、Company 与订阅购买、部署示例、测试工具，以及 docs/Plan 重构和此前远端文档清理回执。所有既有修改均保留并纳入提交审查；不提交环境凭据、依赖、运行数据或原始未成年人数据。

普通文本统一 LF，历史归档快照按 `-text` 保留原始字节，以便本地、Linux checkout 与 Git blob 原始内容一致。新增 Company workspace 的锁文件同步更新；必要的历史验证日志附件显式进入版本控制。

## 验证与同步流程

1. 本地检查候选文件、文档结构/链接、归档摘要、锁文件与提交差异。
2. 备份远端受管工作区和 Git 状态；保留其未提交修改，核对没有未纳入来源的独有业务内容。
3. 推送候选提交到 study-remote，在独立服务器检出目录按依赖顺序构建，运行类型检查、行为测试、隔离 PostgreSQL 测试和前端生产构建。
4. 测试通过后更新远端主工作树，保留线上环境、依赖与当前构建，不以测试构建覆盖正在服务的产物。
5. 将验证回执纳入最终提交，先同步服务器，再推送 GitHub，检查三端提交、树对象、工作区及受管文件 SHA-256。

服务器源码同步与测试不自动执行生产数据库迁移、启用订阅售卖、真实支付/退款、飞书发送或 Company 入口上线。已有生产健康状态单独检查，不将其视为新功能已部署。
