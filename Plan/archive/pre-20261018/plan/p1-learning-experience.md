# P1：学生与教师交互体验（Planned）

## 目的

把复杂的多 Agent 和课程状态转成中小学生可理解、可恢复、可持续完成的项目工作流。

## 工作项

- 学生首页展示当前项目、这周目标、下一步任务、理论/实践门禁和待提交证据。
- 前台只展示一个项目导师入口；在需要时以简短身份标记概念教练、制作教练和评审员。
- 提供 session 工作区：学习材料、互动问题、实践清单、上传证据、反思和保存/继续。
  一节课固定五段（复习/导入 → 理论学习 → 检查 → 实践 → 反思复盘）；反思是独立的
  学生可见环节，不再与「检查」合并展示。
- 计划与单节教学计划之间有**大纲**层：确认计划时派生并冻结，逐节列出目标与分块；
  教学计划按课次**惰性**展开（进入该节课时才生成），不预先生成整份计划的教学计划。
- 提供阶段时间线和产出物列表，明确“为什么现在不能实践”以及“需要补什么证据”。
- 教师工作台展示计划草稿、学生进度、卡点、证据包、AI 初评和待确认事项。
- 处理断网、上传中断、模型忙、权限失败、空项目和教师退回等状态。

## 验收标准

- 学生无需理解 Team Runtime、候选投影或模型配置即可完成一次课程。
- 所有阶段和按钮状态来自服务端投影，前端不推断或写入教学事实。
- 学生能从中断处恢复；教师能定位目标、证据和评审理由。
- 移动端和桌面端均通过信息架构与可用性验收，不能新增冻结导航之外的一级入口。
- 计划的课次数量是学生可见的结构选择（4 或 8 次课），而不是排期字段的副产品；
  无论 4 次还是 8 次，每节课都包含完整的五个分段且分块时长合计恰好等于单节时长。

## 依赖与交付物

- 依赖：`p0-learning-loop` 的 API 投影草案；可与后端实现并行进行交互原型。
- 交付物：学生项目工作台、教师评审队列、状态组件、空/错/离线/权限失败设计和验收截图。
- 核心规范：落实启途智学的课程上下文、恢复会话和练习队列，以及互动课堂块和项目工作区。
