# P0：后端教学闭环与门禁（Planned）

## 目的

让项目从学生意图确认开始，经课程 session、理论掌握和实践阶段，最终进入作品评审；所有事实由领域 owner 写入。

## 工作项

- 梳理 `learning-plan`、`projects`、`mastery`、`works` 的状态转换和事件边界。
- 将“确认意图 -> 创建正式项目”做成幂等命令，并绑定模板版本和计划版本。
- 为每个 session 定义理论块、检查块、实践块和反思块；实践解锁只能由服务端根据 `TheoryMastered` 判定。
- 定义阶段推进命令：学生提交意图、提交学习证据、提交阶段产出、请求评审、教师确认。
- 让 Team Runtime 的候选结果回到领域 owner 做权限、阶段、版本和幂等校验。
- 为失败、过期、重复提交、权限失败和断点恢复定义 Problem Details 错误响应。

## 验收标准

- 学生未确认意图时不存在正式项目。
- 未达到 `TheoryMastered` 时，实践命令返回 `THEORY_MASTERED_REQUIRED`。
- 同一个命令重复提交只产生一次领域事实和一次成长事件。
- 任何客户端或 Agent 都不能直接改变阶段、掌握度或项目完成状态。
- 至少有一条 4 周计划从草稿到归档的服务端集成测试。

## 依赖与交付物

- 依赖：`p0-domain-contracts`。
- 交付物：状态机图、命令/事件合同、服务端实现、权限与审计说明、集成测试。
- 风险：不能把 AI 输出当作正式状态；必须保留候选投影和 owner 接受步骤。
