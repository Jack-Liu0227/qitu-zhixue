状态：供课程设计者逐项审查，未写入模板或团队。待审项 D1、D3、D4、D5。

## 1. 主进度的展示建议

保留 AI 搭档现有“项目进度／团队智能体”两个 Tab。改变项目进度 Tab 内的主次关系，待人工批准后实施：

```text
光学项目
已完成 2 / 16 课；当前第 3 课
第 3 课：光的直线传播与平面镜成像原理
主讲：光学原理与概念教练

本课目标：……
当前活动：理解光线与反向延长线
需要提交：标注物像距离的图、自主解释
当前还缺：……（来自 owner）
继续本活动 / 提交证据

展开查看完整 16 课表
展开查看课程分组与实践门禁
```

“当前第 3 课”不是“已完成 3 课”。如显示百分比，使用 `completedCount / totalCount` 并说明口径；不使用聊天轮数、当前课序号或四阶段位置计算完成率。

不同模板的课时数读取实际冻结 profile，不能把本示例的 16 课写成全局常量。学习阶段如需按教学单元分组，应来自模板中明确的 Theme/Session 关系；缺少分组时先按课时展示，不强套四个治理阶段。新增单元字段必须随原模板合同一起评审。

课表中的完成、当前、锁定和缺失条件来自同一个计划 revision 的真实回执。项目尚未立项时，只展示准备流程和课程预览，不显示正式课时完成率。

建议将板书按钮改成“上一幅图／下一幅图”，页码改成“图示 2/3”，避免它与课内活动或“下一课”混淆。团队任务的“规划项目阶段已完成”建议改成“规划建议已生成”，不暗示学习阶段完成。

## 2. 课程计数需要先决定

建议采用“立项前介绍和意图确认 + 正式 16 课时”。第 1、2 课仍在正式课程内，分别学习观察与假设设计，但不再让已立项学生在第 2 课重复确认是否创建项目。

这要求在新模板版本中调整第 2 课的文案和检查点，并由课程设计者确认。原 profile 不改写。若选择立项前 2 课计入总课程，应另定义探索证据承接和正式课表计数，不能把准备页访问自动当成完成了两课。

## 3. 实际成员与建议职责

| 现有真实成员 | 建议职责 | 需要改正的边界 |
|---|---|---|
| `qitu-intake-assistant` | 立项前澄清、推荐、预览和交接 | 不再作为正式第 1–2 课的长期主讲 |
| `optics-leader` | 项目问题、假设、课程整合与必要协调 | 不要求每轮先让总导师发言，不按阶段包办教学 |
| `optics-concept-coach` | 概念解释、模型与作图、同目标检查和补救 | 允许正常讲解和完整教学示例；公式适用条件由教师审核 |
| `optics-experiment-guide` | 设计比较、受控实践、观察记录与数据分析 | 区分纸面实验设计、注册仿真、真实实验；不自行批准安全或放行实践 |
| `optics-review-assessor` | 报告修订、答辩、反思及评价候选 | 不声称自己直接生成已批准的成长归档或作品通过事实 |

当前每个 role 下多个 Skill 是能力上界，不应全部注入每轮。按当前活动选择其中适用的子集；缺少批准的 Skill、工具或来源时停止该活动，不从其他角色继承权限。

以下课名取当前线上 profile；第 2 课的立项检查点调整、主讲路由和新增能力要求均为待审建议。各 Skill 名是现有 canonical ID 的引用建议，不代表该角色已经获得新增授权。

| 1 现象与观察指标 | 概念教练；必要时实验向导协作 | `pbl-visual-explainer`、`pbl-data-literacy` | 讲解观察与解释区别、动态指标板书；学生提交带指标和单位的观察表 |

| 11 单缝衍射 | 实验向导 | `optics-wave-inquiry`、`pbl-data-literacy` | 注册单缝模型、预测—操作—记录；带 action/版本引用的 observations |
| 12 封闭细雾散射 | 实验向导 | `optics-wave-inquiry`、`pbl-hypothesis-coach` | 注册散射模型、参数比较与适用域解释；实际保存的模拟观察 |

## 5. 现有合同如何扩展

继续使用 `ProjectTemplateSpec → curriculum profile → session → task/evidence`。建议纳入逐课固定开场、当前活动描述、角色引用、披露策略与活动能力要求；它们是新版本的提案字段，尚不是现有 API。

必须补齐已有 `completionSpec`、`requiredSkillIds`、`teachingRequirements` 的实际内容和校验。完成规则需要明确目标、证据种类、最小要求、质量评价和必要门禁，不能只写“看完课件”。

当前编译器即使有 `sessionRoutes`，仍要求课时角色与该宏观阶段 `assignedAssistantId` 相同。建议新合同明确：宏观阶段记录协调责任，逐课路由决定主讲；实际主讲及协作均必须是冻结团队真实成员。新语义使用新合同版本，不能让旧项目静默改变角色。

支持协作应引用明确成员 slot、允许任务及能力范围，并经过现有 Team Runtime 路由校验。只有姓名相似、同属团队或技能相近，都不能授予权限。

## 6. 统一进度与门禁投影

建议由既有领域 owner 组装一份用于 Tutor 的当前学习位置投影，包含真实 plan revision、当前 session、当前活动、主讲、可执行动作和缺失证据。前端课表、聊天开场、课件生成及团队主讲徽标都消费它。

四阶段仅保留在治理及门禁详情中；是否通过门禁必须使用本项目、对应计划／目标及当前有效证据，而非学生曾经通过某个同名门禁。教学单元的完成由其课时回执聚合，交付物提交和批准来自真实版本回执。立项确认门禁已通过，不代表第 1–2 课已经完成。

全课表结束但最终报告未获批准时，应显示“课时活动已完成，成果待审核”。第 8、14、16 课只是检查点，不能因位置自动写理论掌握、批准或归档。
