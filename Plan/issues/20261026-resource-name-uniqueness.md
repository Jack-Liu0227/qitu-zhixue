# 同类别资源名称唯一与设计素材归属

## 问题与范围

团队、助手、模板等配置此前主要约束 ID；不同 ID 可以保存相同名称，导致列表与绑定选择难以区分。
本次保持导航和对象 ID 不变，在现有资源 owner 与数据库表上约束显示名称。

| 资源 | 名称唯一范围 |
| --- | --- |
| 助手、团队、运行时 Agent、模型供应商、MCP 服务 | 各自类别内唯一，包含停用项 |
| 项目模板 | 平台模板内、本校模板内分别唯一，包含归档项；课程版本仍属于同一模板 |
| 知识库 | 相同学校、所有者、项目范围内唯一；已删除库释放名称 |
| 模型 | 同一供应商内唯一；跨供应商仍使用 `(providerId, modelId)` |
| 知识引擎 | 全局配置内唯一，包含停用项 |
| Skills、内置工具 | 服务端继续使用 canonical ID 注册，Skill 创建时名称即 ID，工具注册名称只读；技能页面的会话草稿也不允许与已加载技能重名 |

比较名称时去掉首尾空白、将连续空白合为一个空格，并忽略英文 ASCII 大小写；不改写保存的展示文本。
创建、改名、批量模型保存和知识配置 JSON 导入都遵守规则。编辑自身排除自己的 ID；重试继续走原有幂等机制。

## 服务端、权限与错误

- 数据库迁移 `0053_resource_name_uniqueness` 增加规范化函数与九个唯一索引，为并发写入兜底；Drizzle schema 同步声明索引。
- 服务层对已有目录和内存实现做同样校验；知识引擎和 MCP 配置在原有 revision 校验与事务锁下保存。
- 新建历史兼容运行时入口时，别名记录的显示名称带上其既有稳定 ID，避免与主入口重名；不改变映射、授权或路由，已有记录仍由治理入口处理。
- HTTP 和管家操作回执将已知名称约束冲突映射为 `409 RESOURCE_NAME_CONFLICT`，提示使用其他名称。兼容直接 PostgreSQL 错误和 Drizzle `cause` 包装；不暴露 SQL、冲突行内容或内部索引名。
- 保留 Admin 权限、模板学校作用域、对象权限、审计与回读逻辑。数据库事务失败不提交成功审计，HTTP 失败日志包含错误码和 traceId。
- 管理端现有错误展示使用服务端 message/detail，因此无需改变页面布局；失败时不会显示保存成功。

已归档模板如需改名，应按已有恢复流程处理，不直接修改历史版本正文。
