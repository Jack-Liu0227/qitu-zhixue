# 归档课程恢复与继续编辑

状态：已部署并验证，2026-10-24 23:30。

问题：模板父资源归档后没有恢复操作，元数据和新版本写入都被拒绝。Admin“全部课程”的归档卡片和归档详情需要“恢复并编辑”。

通过原 TemplateGovernanceService / TemplateStore 增加 Admin-only 的 `POST /admin/project-templates/:id/restore`。请求携带 Idempotency-Key 与 expectedUpdatedAt；只接受当前归档父资源和准确修订。事务锁定模板及版本，复制最新历史内容为新可编辑版本，父资源回到编辑态，清除本轮验证标记；旧版本状态、内容、已冻结教学配置和学生项目均不改写。空归档恢复空课程，不制造内容。恢复不自动上架，也不为新版本创建/启用绑定。审计与恢复写入在同一事务；版本一般迁移仍拒绝 archived 迁出。

前端保留幂等重试键，保存后回读实际课程与新版本才能显示成功。后台、断网、修订冲突与权限失败明确提示。点击恢复后进入新版本的教学编排台，其他版本继续按原冻结边界处理。保持现有产品导航。

验证需覆盖历史不可变、学生目录不扩张、可保存新版本、原发布证据不可复用、重复/并发恢复、过期修订、权限、空归档和审计失败回滚。线上不自动恢复现有四个归档课程，供管理员按需要选择。

验证结果：本地依赖顺序构建后 36 项恢复/治理/策略检查和 Admin 类型检查通过；Linux 模板回归 177 项通过，另一个需显式数据库环境的测试在该轮跳过，随后在可丢弃 PostgreSQL 数据库独立运行并通过。实际数据库验证恢复事务、历史版本不变、并发只创建一个版本、审计故障回滚及旧修订拒绝。Fixture 表结构来自原迁移，数据库名称受 `qitu_restore_fixture_` 前缀限制并在完成后移除，不写生产学习数据。
