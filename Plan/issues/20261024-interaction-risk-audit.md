## 开放问题

### I01 / P1：每课检查未形成稳定的对话问答入口

**证据层：源码 + 线上活动配置 + 隔离 schema 复现。**

光学只有第 2 课的 check 使用 mastery；雷霆战机只有第 2、3 课。其余 13 个 check 活动使用 session_response，仍需要学生另行提交表达与依据。表达评价可以用于开放问题，但当前没有统一的“出题 → 在题下回答 → 保存 → 评价”卡片。

`tutor-teaching-context.ts:87` 根据理论/实践目标决定 assessmentAvailable，`tutor.service.ts:804` 再限制到 check。`LessonAssessmentCard.tsx:34` 仅对 teachingMode=zero-base.v1 自动取题；雷霆战机线上没有 teachingMode，需要手动启动正式检查。

更直接的配置断点在 `courseware-tool-schema.ts:18`：光学非实践活动只投影 find_courseware、reuse_courseware、board，已经定义的 choice_question 和 wave_preview 没有进入可调用分支。不能只在提示词里要求“出一道题”来补齐。

线上两份合成项目的持久化聊天分别有 60/24 条 turn、21/8 块 board，均无 quiz/questions 块。这只证明这两个样本没有保存结构化问答卡；不证明系统完全没有口头追问，也不证明正式题目从未作答，因为正式考核另有存储且演示账号有既存掌握证据。

**整改方向：** 按当前活动和证据要求投影工具能力。普通检查走稳定问题实例与课时表达评价，正式考核继续复用既有判题/mastery owner；形成性题不能直接写掌握度。以服务端当前任务下发题卡，学生无需猜测应点击哪种入口。

### I02 / P1：聊天回答、正式答题与课时记录仍然分离

**证据层：源码 + 线上记录接口返回字段。**

`NumberedQuestionList.tsx:23` 将问题和答案拼成文本；`TutorPage.tsx:237` 仅发送普通聊天。实际课时回应由 `LessonWorkPanel.tsx:92` 另行调用 submitLessonEvidence。`LessonNextStep.tsx:25` 已明确提醒聊天回答不会自动保存为活动记录，但提醒不能消除重复填写。

正式考核的 `TutorLessonAssessmentService.answer` 写入判题 owner，不追加聊天消息。`LessonAssessmentCard` 把当前题目与解析保存在组件状态，下一题或切课后替换；`LessonHistory.tsx:51` 只投影提交、观察、作品与反思，线上 evidence 接口也没有正式答题历史字段。后端有判题事实，不代表学生能在历史对话里回看原题、自己的答案和解析。

**整改方向：** 显式题卡的“提交”调用原证据 owner 并幂等保存，随后在原消息下投影真实回执及反馈；普通闲聊不自动当提交。为正式考核增加只读历史投影，保存 questionId、课时/活动、答案版本和判分回执，不复制第二套掌握度事实。

### I03 / P1：已读概念的“再解释一下”可能被去重规则拒绝

**证据层：已编译代码的隔离复现。**

设当前活动有 A、B 两个概念，A 已确认看完、B 尚未展示。学生想对 A 换个例子，`tutor-courseware-activity.ts:68` 会因为候选只覆盖已交付目标而返回“不保存，先讲剩余概念”。复现结果：没有返回 board，新增实例数为 0。这条规则把显式补讲也当成重复生成。

同时，`LessonCoursewareCard.tsx:125` 的补讲/例子按钮只发送“本课/当前概念”，没有携带学生选中的课件 ID 或目标。选择旧课件后求助，模型可能围绕当前另一个概念回应；此项属于代码风险，本轮未通过真实模型单独复现。

**整改方向：** 区分继续教学与显式补讲，求助携带选中实例/目标并由服务端校验范围。补讲允许产生有来源的新版本，但不得新增掌握度或重复推进完成事实。

### I04 / P1：一份旧课件核验失败会关闭有效课件的继续入口

**证据层：已编译代码的隔离复现。**

`TutorCoursewareService.read:61` 遍历最近 12 个课件实例，只要任一实例核验失败就设置全局 blockedReason；`read:71` 以该值决定整个课时 canContinue。

fixture 中旧 review 课件来源不可核验，当前 theory 课件核验正常。结果仍是 instances=1、canContinue=false。前端把“看完了，继续学习”和缺课件时的准备入口都绑定到 canContinue，学生即使拿到有效替代课件也可能继续卡住。

**整改方向：** 逐实例返回不可用原因，当前活动依据它实际需要的有效目标覆盖决定继续条件。撤权课件仍不可展示/确认；不得通过跳过来源校验修复。增加“旧来源失效 + 当前有效替代”恢复用例。

### I05 / P2：板书翻页、理论演示与正式动态实验尚未统一衔接

**证据层：源码与已有浏览器验收，当前轮未重跑全部动画。**

普通生成课件只有 caption、nodes/edges、TeX；`LessonCoursewareCard` 和 `BoardBlock` 提供分步展示，没有相位拖动、波幅叠加或碰撞操纵等通用交互协议。截图中的动态波传播来自单独注册的 WaveOpticsExperimentCard，不能由任意生成板书自动获得。

光学理论阶段的模型 schema 还排除了已有 wave_preview。实践仿真只在当前活动要求 experiment_observation 时投影；看完理论并不自动在同一课件里显示仿真。雷霆战机目前仍是普通板书与本地 Pygame 实践，站内没有可用的游戏运行环境。

历史动态实验默认可见、重复回放和前页图示保留已在[上一轮验证](20261024-dynamic-experiment-visibility.md)。本次接口仍读到 5 个保存的光学实验；不能因此宣称所有新生成课件都具有动态操纵能力。

**整改方向：** 使用注册的低风险理论演示组件，把预测与解释接到相应活动；进入正式实验后仍检查 TheoryMastered、当前课时、参数域和证据回执。新增渲染能力要进入版本化合同，不能允许模型输出任意 HTML/JS。

### I06 / P2：有候选资产存储，尚无线上已发布资产可复用

**证据层：Admin 只读目录和学生课件接口。**

核查时课件目录共 82 个版本，全部 candidate，published=0。`CoursewareService.find:115` 只返回符合课程 hash、用途、目标和授权范围的 published 版本，所以本次快照下跨项目发布资产检索没有可选项。生成过并不等于已经审核发布。

雷霆战机的课件接口返回 null，context 无 teachingMode；模板也未接入光学的 teachingSpec/课件来源授权路径。它的 8 块聊天板书可回看，但没有与光学相同的课件实例、阅读回执和候选复用流程。

另外 `CoursewareService.capture:170` 将新候选 use 固定为 explain，find 却按 use 精确匹配；未来发布后，review/remediate 等用途仍可能找不到合适资产。这是源码风险，不是本次零发布量的唯一原因。

**整改方向：** 在 Admin 维护少量逐课优质发布资产，完成内容/渲染/隐私/来源审核；保持版本和来源范围。雷霆战机需显式接入相应课程合同与授权，不能靠标题“零基础”或客户端硬编码启用。

### I07 / P2：渲染通过不代表科学与教学质量通过；反馈尚无补救动作

**证据层：源码。**

`board-content.ts` 检查节点/边、文本长度、危险内容和至少一张图/公式，不验证物理语义、概念先后或图示是否准确表达材料。知识来源核验证明引用在授权范围内，不证明生成内容正确。项目新生成课件会先显示并保存为 candidate，跨项目发布才要求 Admin 多项审核。

`CoursewareService.feedback:194` 只保存反馈类别、计数和版本修订；前端按钮显示“已记录”，没有自动替换坏图或进入补讲。线上目录反馈版本数为 0，本轮没有发送测试反馈来改动线上资产。

**整改方向：** 关键物理示意优先采用注册模型与审核资产；明确反馈后的下一步，难懂进入同目标补讲、渲染问题提供重试/替代展示、科学问题进入可追踪的内容修订。不要把“来源已核验”展示成“内容已全面验证”。

## 下一轮验收必须覆盖

1. 无既存掌握证据的新合成学生，经正常授权入口学习两模板；不能复用旧掌握度来验收首次出题。
2. 从理论最后一步自然进入检查：每课都能看到问题、提交、反馈和下一步；错答、求助、换例子保持同目标，形成性反馈不越权写 mastery。
3. 直接在问题下提交，刷新后原题、学生答案、解析和评价回执仍可见；网络重试不重复建题或重复提交。
4. A 已看完、B 未学时请求补讲 A；选中历史课件时请求例子；旧来源失效后有效替代可继续。核对权限拒绝仍有效。
5. 正式实验的首次显示、重复回放和跨课时只读；待答题时可回看既有课件，但不替换题目或跳过考核。
6. 至少一个经过审核发布的资产在第二个授权项目中真实复用；记录版本 ID、来源和用途，不把再次生成误记为复用。

优先顺序：I01/I02 问答与记录闭环 → I03/I04 卡住与补讲恢复 → I05/I06/I07 演示能力及资产质量。既有权限、来源核验和 TheoryMastered owner 继续保留。
