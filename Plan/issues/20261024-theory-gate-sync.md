# 理论答题完成后实验仍被拦截

## 场景与根因

本次处理正在学习的项目：学生完成正式理论考核后，实验仍提示需要 TheoryMastered。历史项目的实验回看问题见 [学习链路审查](20261024-learning-chain-gap-audit.md)。

1. 正式答题由 learning-plan/mastery 保存证据，但 Tutor 目标考核和题库答题适配器没有同步 projects 的阶段。题目回执的 `theoryMastered` 是当前课时的判定，不能代表整个项目的所有理论目标。
2. 课时完成接口只保存课时完成事实，浏览器还要单独请求 reconcile。第二次请求失败或中断，会出现“已经进入实践课，项目阶段仍停在理论”的状态。
3. 实验入口先检查项目状态，尚未重验已有证据，因此旧的同步遗漏不能自行恢复。

## 修复

- 项目生命周期 owner 检查冻结课表中全部 `concept_mastery` 目标。全部达标时转入 `practice_ready`，课时反思、教师评价及课时完成事实保持独立。光学检查第 2 课的理论目标；雷霆战机聚合第 2、3 课目标，不能只通过第 2 课就放行。
- Tutor 正式目标考核、正式题库答题和学习计划正式答题 HTTP 入口在持久化结果后同步阶段；形成性题目仍不写掌握度。答题重放也会重试同步。
- 课时完成 HTTP 入口由 projects 编排：保存完成事实后同步阶段。同步失败不回滚已保存证据，使用相同幂等键重试即可恢复。学生端不再依赖额外的完成后 reconcile 请求。
- 实验写入入口确认本人项目、冻结课时、当前活动和作用域后，可调用生命周期 owner 修复旧的理论阶段滞留。仍重新检查真实掌握度、工具权限、协议和参数。作品审核及已归档项目不会重新开放实验。
- 学生主动点击“刷新课时与评价”时，先按已保存的真实证据同步阶段，再读取当前课时。已有达标记录无需重新答题；普通 GET 读取不会偷偷写阶段。
- HTTP 控制器由 ProjectsModule 装配，LearningPlanModule 继续提供计划和进度 owner，避免反向依赖和循环模块。

这不是自动完成课时：理论就绪后，尚未完成的反思、教师评价仍需要真实证据。未进入当前实践活动时仍禁止操作未来课时的实验。

## 权限、幂等与恢复

- 学生身份、计划归属、冻结版本和修订号仍由服务端校验；不接受客户端阶段、掌握度或门禁字段。
- 不新增状态机、掌握度库或数据库迁移；不改历史模板绑定，不注入生产掌握度。
- 阶段变化沿用 `project.learning.reconciled` 审计和 `project.advanced` outbox。内部同步键由原操作键和作用域计算，重试不重复计分或完成课时。
- 原始掌握度错误仍使用 `THEORY_MASTERED_REQUIRED` / `TUTOR_EXPERIMENT_GATE_REQUIRED`；错误课时、活动或版本继续使用相应作用域错误；已关闭实践使用 `TUTOR_EXPERIMENT_PRACTICE_CLOSED`。

远程 15 个 `qitu-*` 应用服务已重启；API readiness 的 PostgreSQL、Redis 均为 `ok`，学生、教师、家长、Admin 和登录页面 HTTP 检查通过。最终学生端构建为 `i17tSVm8Mg8VXQQ4V9rf5`。

隔离测试中的模拟事实只存在内存 fixture，不进入生产；线上验收只使用明确标记的 demo 学生及教师公开 owner 接口。线上演示学生已有先前项目的掌握记录，当前模板会复用有效证据。因此，线上新项目只能证明已有证据的同步与实际实践操作；首次正式作答触发同步由隔离真实判分测试证明，不能把线上跳过检查当作首次答题通过。
